# P0-11 · 完整备份与安全恢复验收

完成日期：2026-10-31。

## 实现

- 登录后新增“备份与恢复”，可后台导出完整 ZIP、查看任务、鉴权下载、上传预检、查看替换前后数量、先导出当前数据、勾选明确确认、查看恢复进度与结果。重开页面可从服务端恢复任务列表；网络失败保留重试入口。
- 一致性快照覆盖全部 23 张业务表及 PDF/图片；包括正式卡片、未确认草稿、调整记录、检查位置、笔记提示收藏、标记与技术纠错、偏好、会话、评分/撤销/更正/重练及冲突证据。清单记录格式、日期、数量、算法、资源长度与 SHA-256；不包含认证或部署配置。
- ZIP 限制压缩/解压大小、条目、JSON 和业务行；拒绝路径穿越、额外/缺失文件、损坏数据、未知版本及非法关联。预检通过最终回滚的隔离 owner 复用真实数据库约束，额外检查来源范围及事件/复习一致性。
- 明确确认后在新不可变命名空间准备资源，再在同用户锁和事务内替换，二次核对修订号，递增代次并与 READY 一同提交。失败保持旧空间；任务 ID 去重。恢复原日期，逾期仍然逾期。解析中的任务恢复为可显式重试的失败状态。
- 设备感知代次变化后重新加载，旧会话不可写；旧 IndexedDB 操作保留为待核对，不自动重放。任务文件保留 7 天，重启处理中断状态和遗留解压目录，成功恢复的结果记录不会随临时包过期变成失败。

接口：[完整备份与安全恢复](../../api/backups-and-restores.md)。决策：[0011](../../decisions/0011-p0-11-backup-restore.md)。

## 真实浏览器恢复演练

使用独立 `p011-browser` 测试账号和 schema，后端 8085、Vite 5177，Edge 桌面 1280px，以及独立 360px/洛杉矶时区浏览器上下文。使用仓库原始 **222 页 PDF**。

1. 导入 158 张草稿、13 章，仅确认 Java 基础 17 张正式卡片；保存笔记、提示、收藏并评分，保留可接续的学习会话。
2. 在独立手机上下文断网保留笔记操作。电脑从页面异步导出，实际点击并保存完整 ZIP；导出后继续改笔记。
3. 上传备份并等待校验，核对当前/备份计数和时间。未勾选确认不能恢复；360px 页面无横向溢出。
4. 明确确认替换并等待成功，比较全部快照表数量、原笔记与收藏、复习 dueDate/首次及最近学习时间/阶段/评分/遗忘次数；实际读取恢复 PDF 并核对字节数，确认会话保留同一未完成进度。
5. 手机重新联网后等待正常在线刷新完成，检测新代次、返回今日学习，旧笔记变为 `needs-attention/EPOCH_EXPIRED` 并保留本地内容，服务端恢复结果不被覆盖；直接提交旧代次请求得到 409。

以上流程已通过，页面运行时异常为 0。脚本：[browser-check.js](browser-check.js)。使用隔离服务和测试账号，通过 `playwright-cli -s=p011 run-code --filename=docs/fixtures/p0-11/browser-check.js` 执行。脚本会替换该测试账号空间，不得改为真实个人账号运行。

证据位于忽略目录 `output/p0-11/`：`browser-result.log`、`roundtrip.zip`、`export-desktop.png`、`restore-preview-desktop.png`、`restore-preview-mobile.png`、`restore-result-mobile.png`、`old-device-mobile.png`；手机预览和旧设备隔离截图已目视核对。浏览器演练发现并修复初始任务列表覆盖新导出任务的竞态；脚本显式等待重联网监听触发的同步结束，避免过早读取旧状态。

## 限制与后续

格式版本 1、ZIP 50 MiB、解压 512 MiB、单 JSON 32 MiB、最多 10,000 条目/200,000 业务行；单 JVM worker，完整替换，不支持部分合并。临时任务文件保留 7 天，须下载长期保管。旧业务资源和失败准备产生的未引用持久化文件延后清理，自动资源垃圾回收与自动备份未纳入本任务。实体手机、HTTPS 发布和完整发布演练仍按 P0-12～13 完成。
