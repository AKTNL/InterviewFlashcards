# P1-05：实时变更通知与按修订增量刷新

日期：2026-11-01。状态：已完成仓库实现与本地验收，尚未发布公网。前置 M5 已签收；原有 30 秒检查及每次变化两次全量快照，是本次改善双设备时效与长答案/历史传输的依据。

## 交付

- V19：持久化修订覆盖和行键日志，业务表延迟触发器在同一事务内记录最终修订；后台解析、删除、复合关联、复习参数与备份恢复均覆盖。
- 异步通知：前台同源长轮询，变化约一秒内提示、约 20 秒心跳；每账号 8 个、单进程 512 个等待上限，等待期间继续检查账号/凭据/会话。
- 增量读取：同一一致性视图返回最终行和删除标记，客户端原子替换状态及游标；断线从旧修订补拉，相关页面按变更表刷新。
- 首次、手动强制刷新、代次切换、游标过期/空档或超限采用全量兜底；通知失败保持定期检查、退避和降级提示。幂等队列、旧代次阻挡、本地编辑及冲突副本保持原有规则。
- 变更日志保留 7 天、每小时事务清理；最多跨 1000 个修订或 5000 个不同键，超过后读全量。日志不保存内容正文，不进入个人 ZIP。

详见 [API](../../api/incremental-sync.md)、[ADR 0025](../../decisions/0025-p1-05-incremental-sync.md)。

## 自动化验证

前端 **204 项测试**、类型检查和生产构建通过。覆盖原子增量合并、删除、复合/数字键、无效基线、通知触发更新、离线补拉、降级退避、隐藏/退出取消、改密拒绝停止重连、恢复全量替换、旧队列与编辑保护、按表筛选及连续变化/跨日刷新；既有幂等、阅读、管理和备份回归保留。

后端 **24 项单元、150 项 PostgreSQL 集成用例**分轮验证通过。首轮全量 148 项发现一处旧迁移计数断言仍为 18，更新到 19 后 UsersFilesIT 12 项复验通过；LearningIT 新增一项实际评分、参数、重练及撤销的增量重建与全量一致性验证，34 项通过；IncrementalSyncIT 最终 8 项通过。新增测试使用 PostgreSQL 18.3 临时容器和随机 schema，无现有部署数据库操作。

后端新增覆盖：连续修改取最终值、删除标记、来源 API 字段与敏感字段过滤、复合关系删除重建、参数数字主键、回滚无幽灵变更、幂等不重复记修订、不同账号不可读、非法/超前/过期/跨代次游标、超过 5000 行兜底、异步等待只由本账号已提交变化唤醒、会话撤销拒绝、服务完全重启后的原游标补拉、7 天清理后全量兜底。

复验命令：前端 `npm test`、`npm run build`；后端设置隔离 `DATABASE_*` 后执行 `mvn -B -ntp -Pintegration verify`。本次全量及定向复验日志分别为工作区 `tmp/p1-05-full-backend.log`、`tmp/p1-05-final-regression.log`、`tmp/p1-05-final-incremental.log`；本机临时目录配置见[本地手册](../../runbooks/local-development.md)。

## 浏览器与验收条件

使用 playwright-cli、两个独立 Edge 浏览器上下文、本地 Vite、实际 Spring Boot 和隔离 PostgreSQL，未模拟业务 API。[结构化请求与结果](browser-evidence.json)保留完整同步请求轨迹；已目视核对[桌面](desktop.png)及[390px 手机视口](mobile.png)。

| 验收要求 | 结果 |
| --- | --- |
| 实时更新 | 桌面保存目标后另一页面 685ms 更新（一次本地测量，非延迟保证） |
| 断线补拉 | 第二页面离线，第一页面连续提交两个修订；重连从旧修订补拉到最新目标 |
| 减少全量读取 | 两页各初始化一次，全程全量请求总数从 2 保持为 2，之后使用 changes |
| 编辑保护 | 另一页面已有未保存输入 11 时，远端变化只提示；本地输入保留，明确重读后才替换 |
| 删除可同步 | PostgreSQL 验证 deck 与复合关系删除均返回 row:null；前端验证移除旧行，不回添已删除数据 |
| 全量兜底 | 代次、过期、超前、超量和无效增量均有后端/前端测试；旧代次队列保留待处理 |
| 通知降级 | 主动阻断通知请求，页面显示定期检查提示；已有同步状态保持已确认 |
| 手机与脚本 | 390px 无页面横向溢出，无 pageerror；预期离线/拦截产生网络控制台错误 |

## 发布与限制

V19 随新前后端一起发布，保留原数据库和文件卷。现有代理 60 秒读取超时大于通知的 22 秒超时，无需流式代理配置。升级前修订若缺少日志会走一次全量；通知不作为持久数据源，服务重启后使用 PostgreSQL 中的游标历史。

初次登录仍取全量，客户端仍保存完整内存快照；日志到期或大型导入允许全量兜底，未实现任意规模分页同步。新同步业务表需同时扩展白名单、行键触发器与页面依赖。此次只完成仓库及本地验收，没有发布公网或进行实体手机复验。
