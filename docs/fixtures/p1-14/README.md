# P1-14：管理 Dashboard 与用户使用统计验收

日期：2026-11-01。仓库实现与本地验收完成，尚未发布公网，未修改线上账号或配置。需求见[开发文档](../../开发文档.md#97-p1-14管理-dashboard-与用户使用统计)，契约见 [Dashboard API](../../api/admin-dashboard.md)，决策见 [ADR 0020](../../decisions/0020-p1-14-usage-dashboard.md)。

## 本次交付

- V17：真实采集起点、独立用户统计锁、登录关闭标记、采集流及每日活动/时长汇总；不回填历史，不改变已有账号与学习数据。
- 全站概览含账号启停/今日新增、当前在线、今日/7 日/30 日活跃、区间应用/学习人数、去重时长、新学/复习、实际保留资源及当前失败导入任务。
- 日期范围、每日趋势、逐用户搜索/分页、最近活跃与时长排序、单用户每日汇总，零使用账号保留。显示上海时区、已应用日期、更新时间、采集起点，并区分未采集、部分覆盖与真实零。
- 前台可信交互、5 分钟空闲阈值、约 30 秒心跳、90 秒在线宽限；首点建起点、超过 60 秒不补算、跨标签页与设备区间并集、上海午夜拆分。后台/失焦/断网/休眠/退出/身份失效停止或重新建起点。
- 心跳仅包含采集 UUID、序号与活动开关；严格拒绝客户端累计秒数，不进入学习同步队列或业务 revision。停止流和退出登录保留关闭标记，晚到请求不能重新打开。
- 原始区间/采集流/登录摘要保留 30 天，每日汇总 12 个月，按小时清理。个人 ZIP 排除统计，整站快照包含全部五张 `usage_*` 表。

## 自动化验证

- 前端 **161 项测试通过**，类型检查与生产构建通过。
- 后端 **24 项单元测试、133 项真实 PostgreSQL 集成测试通过，无跳过**（全量回归及受影响迁移重启测试复验），jar 构建通过。两个原迁移/重启测试的迁移数量断言同步升级至 17。
- 测试使用本次新建的 PostgreSQL 18.3 容器 `flashcards-p114-test`，仅绑定 `127.0.0.1:55444`。集成测试使用随机 schema 并在结束后删除；浏览器使用独立 `p114_browser_final` 和独立文件/临时目录。没有连接既有部署数据库。

`DashboardIT` 9 项覆盖：

1. 首点 0 秒、正常连续区间、相同序号重试、过频、超 60 秒断档、崩溃宽限过期和 revision 不变；第二个普通账号无活动仍显示真实 0。
2. 两个设备/标签页同时写入的真实事务并发，对同一用户取并集；不同用户独立，全站正确累加。
3. UTC 15:59:45～16:00:15 的 30 秒区间在上海午夜拆成两天各 15 秒，不重复、不超过自然经过时间。
4. 停止后晚到心跳不能重开；停用、凭据版本变更立即从在线名单排除，重新启用不恢复旧在线。
5. 未登录、普通用户调用全站/列表/他人汇总拒绝；CSRF、严格字段、无效日期和角色回收；输出不含私人内容或凭据字段。
6. 真实登录/退出关闭本设备流，另设备独立；已关闭登录连首个延迟心跳也拒绝。
7. 上线前 `null` 与真实 0 区分；31 天后清除原始流和区间但保留每日秒数，超过 12 个月清除每日汇总。
8. 使用实际学习评分、同日多次重练、撤销、真实 PDF 的 ZIP 导出/替换恢复，核对恢复后学习量与本人有效记录一致，活动时长/在线不回滚；恢复后次日复习不算新学。
9. 事件 UTC 时间转上海日期，不能用用户学习日直接计入后台；按时长排序、分页与实际文件大小核对。

前端新增测试覆盖：空闲到期、隐藏/离线、网络失败、休眠、时钟倒退、慢请求、身份销毁、定时检查相位接近 30 秒边界；看板未采集/零值、过滤分页、已应用范围的单用户请求、过期响应及权限失败清除数据。原用户管理、学习、同步、知识库等回归保持通过。

## 真实浏览器

使用独立管理员和两个普通账号，桌面 1280px 与手机 390×844px：

- 管理员看到 3 个用户，零使用普通账号显示 0 天/0 分钟、尚无登录/活动；可选择其每日汇总。日期、采集起点及部分覆盖说明明确。
- 用户名搜索、时长排序及单用户每日汇总正常，筛选后旧用户条目移除。
- 390px 检查 `document.documentElement.scrollWidth === innerWidth === 390`；日期输入、卡片和分页适屏，趋势表在内部横向滚动。
- 普通账号通过页面可信点击产生至少两次连续合格心跳；抓取请求只包含 `streamId, sequence, active`，管理接口返回 403，退出发出停止采集。
- 最终构建中，普通账号 36 秒观察期间产生 2 次合格心跳，数据库去重时长约 34.87 秒，退出登录标记关闭；另一普通账号仍为 0。结构化证据见 [browser-evidence.json](browser-evidence.json)。
- 浏览器连续心跳核对曾发现首个心跳与固定 30 秒定时器相位接近时的延迟问题；最终实现每 5 秒检查、约每 30 秒发请求，专门回归及真实浏览器复验通过。

## 复验与首期边界

按[本地开发手册](../../runbooks/local-development.md)配置隔离 PostgreSQL 后，在 `backend/` 执行 `mvn -B -ntp -Pintegration verify`；在 `frontend/` 执行 `npm run build` 与 `npm test`。不要使用生产库运行集成测试。

时长是前台近期交互的服务端区间估算，无交互阅读不计时；异常退出最多有 90 秒在线显示宽限，宽限不增加秒数。真实锁屏/实体手机系统生命周期未单独操作验收，自动化通过隐藏/失焦/定时器暂停及模拟时钟验证停止与重建起点；实体设备可在后续发布复验。每日汇总首期按有效历史服务端计算，文件指标批量核对当前保留资源，适用于现有小规模单站点；未实现实时大屏、行为回放、排行榜或历史资源用量。原始区间清理后只保留每日总时长。公开部署及线上开始采集需按[维护手册](../../runbooks/accounts.md#p1-14-使用统计)配套升级前后端与 V17。
