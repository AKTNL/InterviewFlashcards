## 浏览器与证据

使用真实 222 页 PDF，解析得到 158 张草稿，确认 Java 基础 17 张正式卡片。两个独立登录上下文，电脑与 360px 手机视口，手机时区 America/Los_Angeles；服务端仍使用上海学习日。检查了离线不同评分形成候选、电脑明确更正、手机解除阻塞、笔记冲突双侧保存和显式重新保存、检查位置与偏好同步、页面重新激活刷新、丢失响应后刷新找收据、登录失效后本地持久化及重新认证恢复。

证据在忽略目录 `output/p0-10/`：`backend-verify.log`、`browser-backend.log`、`conflict-resolved-mobile.png`、`today-mobile.png`、`today-desktop.png`。截图已目视核对。控制台中的 401/404 收据探测、离线请求和冲突响应属于刻意验证的错误路径，不代表运行时异常。

原有 `backend/target/app.jar` 被既有开发进程占用，因此使用仅调整构建目录、源码/资源路径及测试工作目录的 `output/p0-10/pom.xml` 完整运行 `-Pintegration verify`，未修改工程 POM、未停止已有服务。独立 PostgreSQL 18 使用仓库内目录和本机 55440；集成测试为随机 schema，浏览器为独立测试账号与文件目录。

按[本地手册](../../runbooks/local-development.md)执行前端测试/构建和后端 `mvn -B -ntp -Pintegration verify` 可重跑自动检查。浏览器复现应使用全新隔离数据库/账号与文件目录：同时打开两个独立浏览器上下文，分别在同一基线提交评分、离线编辑笔记，再联网刷新，核对同步面板及服务端事件数量。禁止以已有个人学习数据作为破坏性测试样本。

尚未进行实体手机、HTTPS 发布或备份恢复演练；这些仍按 P0-11～P0-13 完成。第一版不承诺完整离线学习，完整快照适用于当前个人题库规模。
