## 本次交付

后端提供统一业务事务入口：用户锁、代次检查、请求规范化摘要、操作收据去重、显式版本检查、revision 和收据原子提交。PDF 上传接入该协议；新增资料名称编辑，作为已有实体修改与并发冲突的实际操作路径。V3 增加来源版本和摘要约束，不修改已执行的 V1/V2。

新增修订、完整元数据快照和收据查询。所有读写与收据均按认证用户隔离；快照持用户共享锁，避免 revision 与列表来自不同写入时点。PDF 正文保持鉴权、按需 Range 读取。

前端以 IndexedDB 保存编辑、PDF Blob 和原操作 ID；显示待同步、同步中、已同步、失败、待处理。页面激活/联网/登录后进行服务端预检；丢失响应先查原收据，再判断版本，网络错误退避重试。冲突显示双方名称，明确操作后才使用新 ID/版本提交；旧代次只保留供核对，不自动重放。账号切换清除展示与缓存，异步冲突提交不能把旧账号内容带入新账号队列。存储不可用或配额失败可见，并停止发送。

## 验证结果

| 验证 | 结果 |
| --- | --- |
| 前端测试 | 28 项通过（5 个文件）；涵盖超时/退避、重载收据恢复、冲突两侧内容、旧代次、校验与登录错误、错误收据拒绝、存储失败、CSRF 显式恢复及账号切换 |
| 前端类型检查和生产构建 | 通过 |
| 后端单元/契约测试 | 8 项通过，含规范化摘要的对象顺序、数组顺序和值类型 |
| PostgreSQL 集成测试 | 9 项通过：ApplicationIT 1 项、UsersFilesIT 8 项；V1～V3 空库迁移/重启、原文件、归属与会话基线及本次协议场景 |
| 最终契约修正复测 | UsersFilesIT 8 项再次通过；旧代次收据错误使用一致的 `details.dataEpoch` 字段 |
| 真实浏览器 | Edge，真实 222 页 PDF；6 组核心场景全部通过，未发生页面运行时异常 |
| 手机布局 | 320px 下待同步、冲突详情及操作按钮无横向溢出，截图已检查 |

后端关键证明：

- 同操作 ID 同内容的重试得到原结果、原版本、原业务时间与 revision；换内容被拒绝，跨用户不能读收据。
- 两个并发请求携带同一操作 ID，仅执行一次业务回调；两个独立会话修改相同版本，恰好一个 200、另一个 409 并返回当前版本。
- 业务回调写库后抛错，业务数据、revision 与收据一起回滚；PostgreSQL 触发器强制收据写入失败时，来源名称/版本和 revision 也回滚。
- 改变服务端代次后，旧上传、旧编辑及已有收据的旧请求全部拒绝，当前数据不变。

浏览器关键证明：

1. 上传真实 PDF 并取得收据，来源为 222 页。
2. Playwright 先让 PATCH 在服务端执行，再丢弃响应；刷新后通过原收据确认，仅发送一次 PATCH、revision 仅增加一次、操作 ID 未改变。
3. 阻断同步请求后保存名称和真实 PDF Blob，重载后仍可从 IndexedDB 读取原内容/操作 ID，界面仍显示待同步；恢复网络后两项均获服务端确认。
4. 两个隔离上下文分别编辑名称，服务端值生效后另一个进入待处理；刷新和重试连接不覆盖它。显式接受本地候选时使用新操作 ID 与当前版本，另一设备刷新得到结果。
5. 不合法名称得到失败状态，本地内容保留。
6. 模拟恢复后的快照代次变化，旧服务端列表被清空、旧修改转待处理且不重放。真实数据库旧代次拒绝由上述集成测试验证；本任务未实现恢复业务。

## 复现

常规测试按 [本地开发手册](../../runbooks/local-development.md) 设置 PostgreSQL 环境后运行：

```powershell
# frontend/
npm.cmd test
npm.cmd run build
# backend/
mvn -B -ntp -Pintegration verify
```

浏览器脚本：[browser-check.js](browser-check.js)。使用隔离的测试数据库/schema 和空浏览器会话；源码前端 5173、后端 8080。为一次性浏览器验收预置用户名 `p004-browser`，密码 `p003-browser-only`（测试专用；使用本地手册的 hash 工具生成对应 BCrypt hash）。脚本只针对该测试账号，原文样本使用仓库 `docs/Java+agent八股(高频版).pdf`。

在仓库根目录创建 `output/p0-04/` 后运行：

```powershell
playwright-cli -s=p004 open http://127.0.0.1:5173 --browser=msedge
playwright-cli -s=p004 run-code --filename=docs/fixtures/p0-04/browser-check.js
playwright-cli -s=p004 close
```

没有全局命令时可以用 `npx --yes --package=@playwright/cli playwright-cli` 代替 `playwright-cli`。每次完整复验使用新的隔离浏览器上下文，避免先前验收留下的同名操作干扰定位。

本次本地截图在忽略目录 `output/p0-04/pending-mobile.png`、`conflict-mobile.png`、`epoch-desktop.png`；完整构建日志为 `output/p0-04-backend-verify.log`，最终契约复测日志为 `output/p0-04-backend-final.log`。运行时来源和临时文件不提交版本库。

## 边界

本次完成开发文档 P0-04 的三个验收条件，并为后续业务提供统一入口。评分会话条目绑定在评分业务实现时接入；解析、草稿、评分、完整全范围同步、删除与恢复业务仍分别属于 P0-05～P0-11。浏览器队列保护短期断网和重载，不提供完整离线题库；清理站点数据会移除未同步内容。后端个人空间写入选择串行锁，收据当前不自动过期。
