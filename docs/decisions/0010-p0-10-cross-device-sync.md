# ADR 0010：全范围修订刷新与显式评分更正

- 状态：采用
- 日期：2026-10-31
- 依据：开发文档 §4.11、§6；设计文档 §8.3；ADR 0004、0008、0009

个人规模采用用户修订号与全量权威快照，不引入复杂增量同步。快照覆盖所有学习业务实体与资源元数据，文件二进制按需鉴权读取，解析内部证据和服务端存储键不暴露。用户共享锁保证快照与修订一致；缺失实体和代次变化通过替换状态传播。前端保持在线应用边界，IndexedDB 只负责完整保留待提交操作，不构建第二套离线调度。

活跃页面每 30 秒检查轻量修订，登录、激活、联网、写入成功和手动操作也触发检查。学习日纳入修订响应，以便午夜无新写入时刷新到期集合和额度。服务失败退避；未确认操作和服务端候选共同决定同步状态。数据页面响应远端修订，编辑中的本地内容保留并继续使用原版本保存；再次显式覆盖前发现有新的远端版本，先更新核对内容。

同一复习基线的相同评分只确认重复，不产生第二条有效事件；不同评分保存为待处理候选，并创建幂等收据。采用带候选的成功业务响应，是因为候选本身已成功持久化，需要与 revision/收据原子提交；客户端必须把它显示为待处理，不能把 HTTP 成功当成评分生效。

候选由任一设备明确接受当前结果或更正。更正只针对仍为最新且同一学习日的原事件，采用原评分前状态和时间生成一条 CORRECT 替代事件，关联原事件并保留证据；有效统计排除旧事件，不增加新学数量，不成为又一次重练。最新复习版本或日期不匹配时拒绝更正，接受当前结果仍可用。原评分、复习状态、重练安排、冲突解决、revision 和收据在单事务中提交或回滚。

V9 扩展既有冲突表的代次、操作 ID、版本和解决方式，并增加 CORRECT 事件类型；不修改 V1～V8。恢复功能尚属 P0-11，当前只完成已有代次屏障、权威快照与旧队列隔离的同步接入。
