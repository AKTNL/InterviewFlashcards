# ADR 0020：服务端活动区间并集与可重算学习统计

日期：2026-11-01。状态：采用，仓库实现，尚未发布公网。

P1-14 需要观察使用情况，但登录会话不代表实际前台活动，多标签页和双设备也不能直接累加时长。决定让可见且近期有交互的前台发送只含 UUID、序号和活动开关的心跳，服务端时间确定起点与间隔。首点不计时，间隔超过 60 秒不补算；后台/断网/休眠/退出产生新的采集流。停止写入封闭标记，以抵抗乱序请求重新打开流。

每用户在独立 `usage_user` 行上串行化统计写入，使用 PostgreSQL `tstzmultirange` 合并所有会话、标签页及设备的区间；按 `Asia/Shanghai` 午夜切分。区间并集满足幂等、交换和结合性质，交叠请求或事务重试不能重复计时。不同用户独立；不使用学习写锁、同步收据、data epoch 或业务 revision。当前在线是短时状态，90 秒宽限不作为时长；实时校验账号状态及凭据版本，退出或会话销毁关闭该登录的流。登录摘要在 `usage_login` 中与关闭标记共享行锁，防止退出和首个在途心跳竞争后重新打开在线状态。

每日汇总保留 12 个月，原始时间并集及采集流保留 30 天，按小时清理。迁移记录真实采集起点，不伪造历史在线。区间与每日结果显式区分未采集、部分采集和真实零。学习量不维护不可逆累加器，管理员查询按现存有效评分时间重新计算并按上海日期归档，评分撤销、同日重练及个人恢复后可核对。

Dashboard 查询使用只读一致快照和服务端聚合分页，输出固定元数据白名单；私人题目/答案、笔记、具体评分、文件和凭据仍隔离，组内自愿摘要授权不改变。个人备份不覆盖统计或权限；整站数据库快照完整覆盖。当前适用于现有小规模单站点：资源统计每次批量读取当前文件元数据，学习聚合扫描有效历史，不提供实时大屏或行为回放。规模扩大后应先分析查询成本，再考虑按 epoch 失效的学习聚合缓存；不得改变撤销/恢复口径。

接口与保留策略见 [Dashboard API](../api/admin-dashboard.md)，验证见 [P1-14 记录](../fixtures/p1-14/README.md)。
