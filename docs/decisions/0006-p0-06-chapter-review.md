# ADR 0006：章节聚合编辑与事务确认

- 日期：2026-10-31
- 状态：采用
- 范围：P0-06

以章节版本作为编辑、检查位置和确认的共同并发边界，沿用 P0-04 用户行锁、dataEpoch、请求摘要和事务收据。确认必须基于用户看到的章节清单；另一设备更改任意草稿后，旧版本确认应冲突，不能悄悄导入新的内容。

合并保留第一个草稿，其他输入排除；拆分保留第一份的原 ID，并为后续份创建同章 `parent_draft_id`。不物理删除草稿。操作前完整快照保存在调整记录，`count_delta` 区分人工数量调整与不可变解析报告。正文人工修订统一标识，原始 PDF、原始提取内容及识别报告不被覆盖。

章节确认在单个事务中生成所有有效卡片及来源/追问关联，最后更新章节与检查状态。数据库唯一映射及用户锁保证重复或并发确认不会生成重复卡片。带标记导入需要显式选择，正式标记保留。已导入章节继续通过来源草稿修正现有卡片，保留正式 ID 和学习数据；合并、拆分、排除限定在确认前，正式内容结构调整以后续独立设计处理。

暂时离开仅保留已保存检查结果；显式放弃的范围为当前章节剩余草稿，需要确认和原因，保留证据与调整记录，关闭该章进一步写入。已导入章节不能通过放弃入口删除。此细化不改变设计文档的产品边界。

前端所有写入先持久化到原有 IndexedDB 队列。每章存在未确认/冲突操作时阻止进一步基于旧版本写入。未提交的表单编辑阻止无提示切题/切章；路由离开和关闭窗口提示保留或放弃未保存内容。响应丢失先查询收据；编辑冲突保留双方完整值并允许明确重提，结构操作要求重新选择。聚合读取使用可重复读避免正文、来源和确认状态来自不同时间点。

正式题库先提供本章完整阅读入口，以完成“确认一章，其他章保留草稿”的验收。全文检索、笔记收藏、完整 PDF 阅读器和学习分别留在 P0-07 及后续任务。
