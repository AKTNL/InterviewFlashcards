# ADR 0004：事务收据、用户级写屏障与浏览器待同步队列

- 日期：2026-10-31
- 状态：采用
- 依据：开发文档 P0-04、第 6 节；设计文档跨设备同步要求

1. 业务修改统一进入 `MutationService.execute`。使用数据库用户行锁，使幂等检查、版本检查、业务修改、revision 和收据提交具有一个事务边界；避免“先查收据再在其他事务写入”的并发空窗。当前规模接受同一用户串行写入，不引入分布式锁。
2. 幂等键沿用 V2 的用户/代次/操作 ID 唯一键；摘要包含资源身份、操作类型与规范化逻辑负载。原结果存为 JSONB，并原样按语义重放；恢复代次检查优先于收据。
3. V3 为现有来源增加显式版本；资料名称编辑提供可真实操作的版本冲突路径。名称编辑不改变存储键、解析或学习状态。此路径用于验证协议，不提前实现学习设置、草稿或评分功能。
4. 快照持用户共享锁，与写屏障协作，返回同一修订下的元数据；大文件仍按需读取。恢复和后台业务以后复用同一屏障，禁止绕过。
5. 前端直接使用浏览器 IndexedDB，按操作独立存储结构化内容和 PDF Blob。事务提交失败时停止提交；重载和请求结果未知时保持原操作 ID。界面只根据服务端确认显示已同步，不以列表刷新或本地保存冒充成功。
6. 请求重试先查询收据，再检查实体版本；这一顺序能区分已成功但丢失响应与真实并发冲突。网络错误退避重试，冲突/校验/旧代次停止自动重放。队列按用户过滤，代次变化保留本地值并清除服务端缓存。
7. 认证及 CSRF 不属于业务收据。业务写入后续扩展、评分会话绑定、全范围冲突闭环和备份恢复按各自任务落实；本次不提供通用任意 SQL/任意资源修改 API。

已知取舍：待同步数据属于当前浏览器与站点，不承诺清理浏览器数据后恢复；确认历史当前保留在本地、上传成功后释放大文件。跨标签页同时提交同一操作由服务端幂等防重，完整全业务多设备同步在 P0-10 扩展。
