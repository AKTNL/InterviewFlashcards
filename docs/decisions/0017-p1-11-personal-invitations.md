# ADR 0017：受控个人邀请码与两步注册

日期：2026-11-01。状态：采用。

P1-08 仅能通过维护命令发码。P1-11 将账号信息、邀请码和密码入口集中在“个人中心”，与 PDF“我的资料”区分；好友先验证邀请码，再设置账号，成功后登录。预校验只帮助输入引导，不能获得会话、保留名额或跳过最终验证。

个人码固定 7 天、1 次，同时最多一枚有效码。权限和累计成功额度由受控命令逐账号设置，默认未授权；全站累计注册上限可配置，默认 100 且注册默认关闭。旧维护邀请码继续有效，也受全站开关和上限控制。授权修改保留已成功计数，撤销、过期、学习恢复均不返还成功名额。

采用 V14 的独立权限表及全站准入行锁，将生成、撤销、权限变更和注册串行化。注册使用邀请行锁处理与旧维护撤销的竞争，在同一事务创建用户、初始化偏好、记录使用和邀请人成功数。该选择适合当前小规模单站；代价是 BCrypt 注册期间其他准入事务等待，不影响正常学习读写。扩大规模前可评估原子计数与更细锁，不能取消全站及个人额度的一致性。

数据库只保留随机 token 摘要，生成响应展示一次。页面重新进入只展示邀请 UUID 的脱敏标识和状态；丢失响应先查状态，无恢复明文接口，无自动重放或自动替换。撤销与重新生成分为两个明确动作。邀请人只能看到次数，不能看到受邀人的用户名或学习情况。学习 ZIP 白名单不变，账号、权限与邀请永远采用服务器现状。

接口见 [个人邀请契约](../api/personal-invitations.md)，维护见 [账号手册](../runbooks/accounts.md)，验证见 [P1-11 记录](../fixtures/p1-11/README.md)。
