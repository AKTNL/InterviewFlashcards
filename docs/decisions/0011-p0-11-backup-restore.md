# 0011 · P0-11 完整备份与安全恢复

日期：2026-10-31。

选择版本化 ZIP + 全量 JSON + 不可变 PDF/图片，而非数据库转储。备份可迁移到另一个登录用户，但不携带账号、凭证、内部路径或可执行 SQL。V10 只扩展既有任务表，不修改 V1～V9；同时修正 foundation 中不足以容纳 AWAITING_CONFIRMATION 的状态列长度。

一致性沿用既有 owner 锁协议，短事务读取全部业务表及资源键，然后在锁外哈希、压缩。恢复在短事务外预备新文件，最后检查 epoch/revision、替换数据库并递增代次；结果状态也与替换一同提交。所有资源使用新的随机键，失败保持旧空间。已提交恢复永远不会因任务重试或重启重复执行。

预检使用不可见的临时 owner 事务并最终回滚，复用真实 PostgreSQL 约束与附加业务校验，避免另建一套容易漂移的 FK 验证器。业务主键与所有结构化引用重新映射，归属强制使用认证用户，接收的包不能用 userId 指定另一个空间。JSONB 字段直接取自原始行以区分领域 JSON null 和 SQL NULL；只有可空 raw_evidence/region 将 null 还原为 SQL NULL。事件先后次序保留，调度日期不重新计算。

恢复是“替换整个空间”，没有部分导入或自动合并。确认基线在接收确认和实际提交时各检查一次，期间继续学习会使预览失效。离线设备旧队列保留待核对，旧编辑器与会话在代次变化后销毁并重新载入。新代次不接受旧操作，恢复过往日期也不会把逾期日延到今天。

单进程任务由独立的第二个调度线程执行，与 PDF 解析分开；文件操作不持有 owner 写锁。压缩包和解压配额在读流时执行；格式版本 1 是严格契约。临时备份保留 7 天，完成恢复的结果与学习资料独立保留。旧业务文件延后清理；尚不实现多副本 worker、自动资源垃圾回收、定时备份或通用旧格式迁移。将来增加格式必须有显式迁移和对应验证，不默认接受。
