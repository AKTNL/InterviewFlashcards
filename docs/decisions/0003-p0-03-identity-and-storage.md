# ADR 0003：P0-03 用户、来源文件与基础模型

- 日期：2026-10-31
- 状态：采用
- 依据：[开发文档 P0-03](../开发文档.md)、[ADR 0001](0001-p0-01-baseline.md)

## 身份与会话

使用 PostgreSQL `app_user`、Spring Security `UserDetailsService`、BCrypt 和服务端会话。只从 `ACCOUNT_USERNAME`、`ACCOUNT_PASSWORD_HASH` 预置账号，不保留明文密码、不开放注册、不使用框架临时生成的默认密码。提供离线交互式 hash 工具，默认 cost 12，启动接受 cost 10～16 的 BCrypt hash。

同名账号在启动时更新配置 hash，保留用户 ID、学习时区、数据代次和修订号；可通过更新 hash 并重启来轮换密码，重启使现有内存会话失效。修改账号名会新建独立空间，不是账号重命名；首版不提供账号管理或跨用户迁移。

CSRF 保持开启，前端从专用 JSON 端点获取掩码 token，通过头提交。认证、会话 ID 更换和退出使用 Security 内建过滤器。认证后擦除 principal 中的 hash，DTO 不暴露凭据。前端确认 401 后清除当前用户、离开受保护页面；请求失败保留分类错误，不把网络故障当成已退出，也不自动重放写入。

## 存储边界

`FileStorage` 封装流式暂存、摘要、发布、读取和回滚清理；`LocalFileStorage` 仅接受 UUID 存储键。正式文件与临时目录不可相同或嵌套，multipart 暂存同样使用配置的绝对临时路径。正式文件不由静态服务器直接暴露。

PDFBox 3.0.5 负责上传阶段的格式与页树检查，解析目录和生成草稿仍属于 P0-05。50 MiB 单文件、51 MiB 请求限制在浏览器、后端和代理落实。暂存流一次计算大小与 SHA-256；发布时先复制到正式目录内临时文件，再原子改名，支持临时卷和文件卷位于不同文件系统。

文件登记事务对用户行加锁，再核对指纹、发布文件、保存来源。事务失败清理已发布文件；正常退出删除上传暂存。进程在文件发布后、数据库提交前突然终止时仍可能留下无引用文件；此类文件无法通过鉴权 API 寻址，后续运维可按数据库引用核对清理。本阶段不引入后台清理器，也不对未知文件自动执行删除。

来源和图片读取必须以 `(userId, id)` 查询。使用 Spring MVC `Resource` 支持 Range/HEAD，拒绝通过路径、文件名或未经归属校验的资源键访问。图片限定 PNG/JPEG；不提供任意 HTML/SVG 上传。

## 模型演进

保留 V1 原样，V2 为开发文档第 3 节各实体建立基础表、稳定 UUID、归属、版本字段与必要唯一约束。子实体以 `(user_id, parent_id)` 复合外键引用父实体，防止程序遗漏校验时创建跨用户关系；章节检查位置也必须属于该章草稿。

关键约束包括用户内来源指纹、每来源单个导入任务、来源条目去重、草稿到正式卡片唯一映射、每卡片唯一个人整理/复习状态、每用户唯一偏好，以及按用户/代次/操作 ID 的收据与复习事件唯一键。JSONB 仅存内容块/证据/未来协议数据，能用关联表表达的归属关系不塞进无约束数组。

当前实际读写的 User/SourceDocument/Asset 使用 JPA 实体与仓储；其余表是后续任务的持久化基础，按相应任务增加字段、映射、业务状态转换与事务服务，不建立虚构的成功接口。V2 中存在同步、复习、备份基础表不代表这些行为已经实现。
