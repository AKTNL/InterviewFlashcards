# ADR 0014：邀请码注册、独立账号与密码维护

- 日期：2026-11-01
- 状态：采用（仓库实现；公网版本按发布手册升级）
- 对应：P1-08；替代 ADR 0003 中“每次启动覆盖配置密码”的行为。

## 决策

继续使用 PostgreSQL `app_user`、BCrypt cost 12、Spring Security 内存会话和 CSRF。注册默认关闭，启用后必须使用维护者生成的 256 位随机邀请码。数据库仅保存 SHA-256 摘要；额度行锁、账号与规范化名称预留、默认学习设置及使用记录在同一事务提交。失败不占额度，注册成功不自动登录，响应不确定时引导登录，不进入离线队列。

新用户名 strip 后按 Locale.ROOT 转小写，3～32 位 ASCII 字母/数字/下划线、字母开头，排除保留名。注册和登录规范化新账号，已有账号始终优先使用原样精确登录，不改名。V11 为已有名称建立小写预留；即便旧库有大小写不同的多个账号，仍保留各自身份并阻止注册再占用。显示昵称与登录名分开。

第一次升级启动，在新表 `preset_identity` 绑定配置用户名对应的 LEGACY 用户，保留 ID、hash、dataEpoch、revision 和全部业务数据。空库首次创建 PRESET 用户后绑定；同名 REGISTERED 用户禁止接管。绑定存在后，无论重启的环境用户名/hash 是否变化，都不再更新密码、重命名或新建预置空间。启动仍要求合法初始化配置。忘记密码用数据库权限受控的交互维护命令，不再通过改环境 hash 重置。

每个会话主体保存登录时的 `credential_version`，每次 API 请求与数据库核对。应用改密和维护重置在更新 hash 的同一事务递增版本；该账号所有旧会话下一次请求即被拒绝并销毁，不需要枚举 JVM 会话。正常后端重启仍要求所有用户重新登录。已有的在途请求按其请求开始时认证的用户执行。

登录按来源地址及规范化账号持久化限流；注册、改密按来源地址限流。15 分钟窗口中登录同来源最多 60 次、同账号 20 次，注册/改密同来源各 20 次。重启保留窗口，旧桶按小时清理。只信任 servlet remoteAddr；生产后端仅暴露给 Nginx，由 Nginx 覆盖转发头并由 Tomcat 解析可信代理，禁止直接开放后端端口。

前端用用户 ID 分隔队列、用户 ID + dataEpoch 作为页面实例键；切换会取消旧请求，旧结果不进入当前页面。LocalStorage 非敏感随机标记配合 BroadcastChannel 通知同源标签页，发送请求前及响应完成后再次核对标记。旧标签页停止同步、清空内存页面并要求重新确认身份。业务 API 发送 `X-Account-ID`，服务端检查它是否与会话一致，覆盖共享 Cookie 先变化、通知尚未送达的窗口。服务端始终从会话取得归属；该头既不能指定用户，也不是授权凭据。密码/邀请码不进入持久化存储或学习备份。

个人二进制资源与服务端备份/恢复副本默认合计 512 MiB、20 个来源，同时最多 2 个导入、2 个备份/恢复任务；全站最多 20 个待处理任务，文件和暂存目录合计 5 GiB、磁盘保留 512 MiB。配置可调，具体计量见 API。来源新增、任务登记、导出发布、恢复替换执行服务端校验，容量锁在用户写锁之后获取。不可变文件的发布由单 JVM 同步检查全目录实际占用，含未引用旧资源；导出/解包提前预留工作空间。沿用单 JVM worker，不支持多后端共享文件目录。限额采用保守拒绝，不能以清空学习记录绕过物理占用保护。

## 验证与影响

见 [P1-08 验收](../fixtures/p1-08/README.md)。既有各业务模块的用户归属外键与 `user_id` 查询继续使用；备份白名单仍只有学习数据，不新增账号、邀请、凭据版本、预置绑定和维护审计。

不开放匿名重置、无邀请注册或题库共享。升级包含 V11，回退要用升级前完整数据库/文件快照，不能让旧版本启动覆盖新密码。实体设备、公网证书及资源预算在部署时复验。
