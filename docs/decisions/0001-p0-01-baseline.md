# ADR 0001：首版技术与数据规则基线

- 状态：采用，作为 P0-02 及后续任务的实现依据
- 日期：2026-10-31
- 依据：[开发文档](../开发文档.md) §2、§4.2、§5～7；[解析验证记录](../fixtures/p0-01/README.md)
- 范围：当前 PDF、个人单用户入口、在线应用。本文确定实施方案，不表示后续功能已实现；未来修改另写 ADR 并说明迁移。

## 1. 技术栈与部署

| 项目 | 选择 | 理由和边界 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite、Vue Router、Pinia | 长答案/草稿/学习状态使用明确类型和组件；P0-02 固定依赖版本与锁文件 |
| 后端 | Java 21、Spring Boot 3、Spring Security、Bean Validation | 统一事务、认证、参数校验和后台任务；P0-02 固定 Boot 的具体小版本 |
| 数据库 | PostgreSQL、Flyway；Spring Data JPA | 使用真实数据库验证唯一约束与事务；显式实现乐观锁与修订号，不依赖前端去重 |
| PDF | Apache PDFBox 3.0.5 提取及区域渲染；PDF.js 查看原文 | 本次实测可读取 222 页和全部 158 个命名目标，跨页与标题边界可追溯。Python 仅用于离线验证，不是生产解析依赖 |
| 存储 | 服务端持久化文件目录 + 数据库元数据/归属；封装文件接口 | PDF/图片不可变引用，文件名只作展示，不拼接存储路径 |
| 部署 | Docker Compose：同源 Web 反向代理、单后端、PostgreSQL | 数据库和来源文件独立持久化卷；生产 HTTPS；首版不引入消息队列或 Redis |

后端任务进度存入数据库，重启后可恢复或明确重试；任务线程未完成不能标记成功。升级 PDFBox 必须重新运行本次回归，不将解析数量一致等同于版式/答案已经校对。

## 2. 当前 PDF 与内容保留

目录 `/Link` 指向命名 `/XYZ` 目标，页码来自真实页树，`topPdf=732` 对应 792pt 页面左上原点的 `y=60`。当前每题从不同物理页开始，但算法仍按“目录链接 + 正文标题”定位边界，使用半开范围 `[start, nextStart)`；不采用一页一题。文字框采用转换后 em 高度的保守估计，不声称是精确字形外框。

规范化展示章节名（如 Reids → Redis）并保留原名。跨页、空白内页、多来源范围、追问位置和原始文字均保存，不能用单个页码代替。追问不独立调度。

代码、表格和图示自动重建尚不可靠：原始片段与坐标原样保留；候选带 `LAYOUT_REQUIRES_SOURCE` 及具体异常标记，提供来源物理页/范围并可用工具渲染整页。生产阅读须保留相应原文区域或明确原文入口。不能猜数字、修补源文技术错误或用摘要替换完整答案；人工纠错和原文分别存储。带标记导入需要用户明确选择。

## 3. 账号与学习日

首版使用单用户预置账号与密码，不开放注册。账号初始化配置由环境提供，密码使用 Spring Security BCrypt 散列；服务端会话 + 同源 Cookie，生产 `HttpOnly`、`Secure`、`SameSite=Lax`，写请求启用 CSRF。文件、草稿、卡片、学习、备份接口均校验 `userId` 归属，单用户不豁免归属检查。

时间戳保存 UTC；服务端用户学习时区固定 `Asia/Shanghai`，首版不允许随意变更。服务端生成 `learningDate`；`dueDate` 是该时区日期，`dueDate <= today` 且章节在范围内才进入到期集合。跨设备不使用浏览器日期统计。

仅有效首次评分计为已学。今日新学按今日首次有效评分的不同卡片计；今日复习按今日复习过的已学卡片计，同日首次学习后的重练不再计复习题。浏览、收藏、展开答案和笔记不改变调度。撤销与恢复按有效事件核对统计。

## 4. 三档调度 `rules-v1`

间隔表 `[1, 3, 7, 14, 30]` 天，`stage` 初值 `-1`。间隔从本次服务端学习日计算，不以 N×24 小时计算。服务端参数可配置，任何规则变更须记录新算法版本；旧事件及到期日期不批量重算。这是首版候选参数，不代表科学最优值。

| 评分 | stage | 下次复习 |
| --- | --- | --- |
| 记住了 | `min(stage + 1, 4)` | 更新后阶段对应间隔，最高保持 30 天 |
| 模糊 | `max(stage - 1, -1)` | 1 天后 |
| 不会 | `-1`，遗忘次数加 1 | 1 天后，本轮后部可追加一次重练 |

同卡同学习日的后续练习均算同日重练：保留事件和最近评分，不推进阶段、不再增加遗忘次数或新学/复习卡片数，不把日期推迟到原定 dueDate 之后。自动追加重练每卡每日、每会话最多一次，允许跳过结束，不能通过重开会话无限追加。次日及之后按正常规则调度；提前练习先明确提示。

撤销限定当前会话内、当前用户最近一次且无后续卡片变更的有效评分，通过版本检查并保存补偿关系，恢复前状态、会话位置和重练安排；撤销首次评分回到未学。显式“重新学习”保留历史和首次学习时间、dueDate 设今日，不重复计新题。

## 5. 写入与冲突

服务端为数据源；IndexedDB 保存未确认操作与原始内容。操作后刷新、页面重新激活时拉取；短时断网可重试，首版不承诺整套离线学习。

写入附带 `operationId`、`dataEpoch`，更新附带 `expectedVersion`，评分绑定会话条目。幂等键为用户/代次/操作 ID；请求摘要、业务更新和结果收据在同一事务。相同请求返回原结果，同 ID 不同内容拒绝。版本检查只允许一个写入成功，响应包含版本、修订号与服务端时间。

| 冲突 | 首版处理 |
| --- | --- |
| 笔记、草稿或偏好并发编辑 | 保留本地与远端内容，由用户选择/合并，携带新版本和新操作 ID 提交 |
| 同一复习状态提交相同评分 | 第二次作为重复候选，返回当前结果，不再推进或生成第二条有效评分 |
| 同一状态提交不同评分 | 首个生效，第二个保存待处理候选，不覆盖、不重复累计 |
| 选择候选更正评分 | 基于同一原始评分前状态重算并替换冲突链的有效结果，不当成第二次练习；已有后续学习时拒绝直接更正 |
| 会话被其他设备推进 | 返回最新会话/卡片状态，刷新队列；额外练习由用户明确进入 |
| 登录失效、校验失败、冲突、旧代次 | 分别重新认证、修正、人工处理、隔离待核对；不统一盲目重试 |

所有正式卡片 ID 稳定，章节再次确认幂等；删除/恢复推进修订号并使相关旧会话失效。用户内容在收到服务器确认前不能显示为“已同步”。

## 6. 完整备份 `formatVersion=1`

ZIP 包含 `manifest.json`、`data.json`、`sources/`、`assets/`。清单记录格式版本、时间、实体数量、算法版本、每文件长度及 SHA-256。导出使用数据库一致性快照和固定的不可变资源清单；包含正式内容、草稿/调整/检查进度、来源、个人整理、事件（含撤销关系）、当前复习状态、偏好和可恢复会话。不包含账号密码、Cookie 或部署密钥。

恢复到当前用户空间，不信任备份中的用户归属。替换前限制大小/条目数、禁止路径穿越，校验版本、校验和、关联及调度/事件一致性；未知新格式拒绝，旧格式仅走显式迁移。先展示替换范围并允许导出当前数据，确认绑定当前修订号，写入变化后须重新预览。

资源先准备到新命名空间，短时阻止该用户写入并等待进行中的事务；数据库单事务替换，成功后切换数据并递增 `dataEpoch` 和 revision。失败保留旧空间，旧资源延后清理，恢复任务自身去重。保留原 dueDate 和学习日，过期仍过期。旧设备清理服务端缓存并重新拉取，旧待提交操作转为待核对，不自动重放；传输收据不照搬旧代次。

首版只提供完整替换恢复；自动备份、合并恢复和部分恢复留后续任务。
