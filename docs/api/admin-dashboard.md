# P1-14 管理 Dashboard 与使用统计

V17 随前后端一起升级。普通学习接口和修订协议保持原口径；看板按 `Asia/Shanghai` 自然日聚合，时间戳以 UTC 保存。需要登录、逐请求有效账号和 `dashboard.read`；普通用户不能访问全站或他人统计。响应只含白名单元数据，不含私人题目、评分明细、笔记、文件、凭据、会话 ID 或活动区间。

## 查询

| 方法及路径 | 参数与结果 |
| --- | --- |
| `GET /api/admin/dashboard` | 必填 `from`、`to`（ISO 日期，含首尾日）；返回 `summary`、按日 `days` 及统计元数据 |
| `GET /api/admin/dashboard/users` | 同上；可选 `search`（用户名/昵称字面包含，最多 100 字）、`sort=recent\|duration`、`page=0`、`size=10`（1～50）；服务端汇总、排序和分页，包含零使用账号 |
| `GET /api/admin/dashboard/users/{id}` | 同样日期范围；返回用户标识/昵称与每日汇总，不提供私人明细；平台内容身份返回 404 |

日期范围不能超过今天、不能倒置，起点最早为当前上海日期减 12 个月，最多 366 个自然日。无效参数返回 400。管理查询使用只读一致快照，不锁住学习写入。用户列表按最近活跃降序（空值最后），或按区间时长降序、最近活跃及 ID 稳定排序。

公共元数据为 `timezone`、`from`、`to`、`updatedAt`、`collectionStartedAt`、`retainedFrom` 和 `activityCoverage`。后者为 `UNCOLLECTED` / `PARTIAL` / `COLLECTED`；迁移只记录真实采集起点，不回填历史。区间完全早于采集日时，活动人数、活动天数和时长为 `null`，按日也用 `null`；采集后没有使用为真实 `0`。跨越采集起点的区间汇总仅含已采集部分，页面标明覆盖不足。学习量可由现存有效事件追溯，因此与活动采集覆盖分别展示。

`summary` 包含用户总数、启停数、上海今日新增、当前在线、今日/近 7 日/近 30 日应用活跃人数、所选区间应用活跃与学习活跃人数、有效在线秒数、新学/复习量、当前全站存储与当前 FAILED 导入任务数。平台内容身份不计入用户数，平台资源/失败导入包含在全站资源指标内。存储根据当前保留资源的实际文件大小批量核算，包含来源、图片、分享快照及备份/恢复包；不表示整个文件卷或孤儿文件的磁盘占用。

用户行字段：`id, username, nickname, enabled, last_login_at, last_active_at, online, active_days, seconds, new_count, review_count, claims, storage_bytes`。使用天数、时长、学习量和知识库领取数属于所选区间；登录、最近活跃、在线与存储属于当前状态。每日点字段：`day, active_users, learning_users, seconds, new_count, review_count`。全站时长可超过单日 86400 秒（不同用户相加），同一用户每天绝不超过 86400 秒。

## 学习与应用活跃口径

应用活跃来自合格前台心跳，每区间按不同用户去重；学习活跃来自有效评分。最近登录来自真正登录成功记录，两者互不冒充。

学习汇总从 `RATE` / `CORRECT` 且未被 `undo_of` 补偿的现有事件重新计算。以事件 `created_at` 转入上海日期，按用户/卡片/自然日去重；每卡首个有效日算新学，之后有效日算复习。同日重练不重复增加题量，UNDO/RELEARN 补偿本身不算完成。个人学习日与设置不变；后台不直接累加不同个人学习日的“今日”数字。个人 ZIP 恢复后按恢复的有效事件重算，活动、登录、权限及审计不回滚。

## 前台活动采集

`POST /api/usage/heartbeat`，需要有效登录、CSRF 和当前账号请求头；请求严格只接受：

```json
{ "streamId": "采集流 UUID", "sequence": 1, "active": true }
```

不接受用户 ID、活动内容、客户端时间或累计秒数。用户由当前会话确定，服务端仅保存会话 ID 的 SHA-256 摘要以关联采集流。返回 `true` 表示采纳/停止；重复、过频、乱序及已停止流返回 `false`，不续在线、不计时。`active:false` 封闭当前流；停止标记防止晚到活动请求重新打开计时。

前台可见且最近 5 分钟有可信键盘、点击、滚动、触摸时约每 30 秒发送一次；本地每 5 秒检查是否到期（不等于每 5 秒发请求）。后台、失焦、离线、pagehide、退出、账号变化或会话失效时停止。恢复前台须有新交互，产生新流；休眠导致定时检查间隔超过 45 秒或系统时间倒退也建立新起点，不补传离线时段。仅发送活动时间元数据，无输入正文、按键内容或阅读对象。

服务端对同一流最短接受间隔 10 秒；新流最短用户间隔 2 秒；每用户最近 90 秒最多 32 个流，超出返回 429。每流序号去重，只使用服务端接收时间。首个心跳只建立起点；相邻接收间隔不超过 60 秒才形成有效区间，超过不补算。所有标签页、登录会话及设备区间在用户独立统计锁下取并集，再按上海午夜切分。业务修订号、epoch 和同步队列均不参与。

当前在线要求最近 90 秒有未停止合格心跳，且账号启用、已完成改密、凭据版本仍有效。退出/Servlet 会话失效立即关闭该登录会话各流；停用和凭据更换立即使旧流退出在线。崩溃或无法送达停止事件时最多保留 90 秒在线宽限，宽限本身不增加时长。浏览器活动元数据用于估算，不等价于精确操作工时；长时间阅读无交互不计入。

## 保留、备份和运维

- `usage_collection`：迁移时真实 UTC 采集起点。
- `usage_user`：独立统计锁与最近活跃时间；不保存行为正文。
- `usage_login`：登录会话摘要和关闭标记保留 30 天，与采集共享行锁，防止退出与首个在途心跳竞争后重新显示在线。
- `usage_stream`：最近接收时间、序号、停止状态、会话摘要及凭据版本，保留 30 天。
- `usage_daily`：每日活动与去重时长保留 12 个月；用于去重的原始时间并集仅保留 30 天，之后清空 `spans`，保留已核算 `seconds`。

每小时运行清理，可用 `app.usage.cleanup-ms` 调整检查间隔（不改变保留期）。按上海日期删除早于“今天减 12 个月”的汇总；清理只涉及统计表。原始区间关闭并清理后不能再重新推算细粒度轨迹。整站数据库 dump 包含五张统计表；个人 ZIP 白名单排除全部统计表，也不包含会话摘要。升级、回退和恢复说明见[维护手册](../runbooks/accounts.md#p1-14-使用统计)。
