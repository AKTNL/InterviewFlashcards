## 1. 使用方法与优先级

### 1.1 优先级含义

| 优先级 | 含义 | 交付要求 |
| --- | --- | --- |
| P0 | 第一版必须具备的功能及数据正确性保障 | 全部完成并通过验收，才可称为第一版完成 |
| P1 | 第一版可用后的效率、体验与运维增强 | 不阻塞 P0 发布，按实际使用反馈实施 |
| P2 | 新资料适配、AI、语音等扩展能力 | 完成核心闭环并验证需求后再启动 |

**优先级不等于开发顺序。** P0 内部按照 `P0-01 → P0-02 → … → P0-13` 推进；后面的任务依赖前面的数据结构、接口或能力。任务表中的编号同时作为后续开发和验收的引用编号。

每次开发建议选取一个任务，必要时再拆成更小的提交：先核对前置条件，再完成数据迁移、接口、页面及相应验证，最后按验收条件检查。未通过验收的任务不标记为完成。

### 1.2 第一版边界

P0 必须形成以下完整流程：

**同一用户登录 → 上传当前 PDF → 自动生成导入草稿 → 逐章检查并确认 → 设置学习范围 → 主动回忆与完整答案阅读 → 三档自评 → 到期复习 → 跨设备继续 → 完整备份与恢复。**

- 手机、电脑同步和主动备份恢复都是第一版要求，不能仅做浏览器本地存储后就结束 P0。
- 先适配 [Java+agent八股(高频版).pdf](Java+agent八股(高频版).pdf)，不承诺扫描版或任意排版 PDF 的识别效果。
- 以个人使用为起点，不提供公开注册、题库分享、多人协作或社交功能。
- 一道主问题默认对应一张参与调度的主卡片；追问随主卡片展示。导入检查时支持人工拆分，拆分结果可以生成独立主卡片并保留关联。
- 自动摘要、自动判断回答正确性、录音和模拟面试不进入 P0。

上述为已交付 P0 的范围。2026-11-01 新增“注册账号，方便和朋友一起学习”的后续需求；P1-08 邀请码注册与独立账号、P1-09 题库复制、P1-10 学习小组与自愿摘要已完成仓库实现和本地验收，尚未发布公网。详见第 9 节，不改变 P0 的完成记录。

## 3. 数据模型与不可破坏的规则

### 3.1 核心实体

以下是逻辑模型，实际表名可调整；各业务数据均关联 `userId`，外部接口使用稳定 ID。

| 实体 | 关键字段或关系 | 作用 |
| --- | --- | --- |
| User | id、账号、密码散列、learningTimezone、dataEpoch、revision | 用户归属、学习日及恢复代次 |
| SourceDocument | id、userId、原文件名、SHA-256、页数、文件引用 | PDF 去重与原文访问 |
| ImportJob | id、sourceId、状态、阶段、进度、错误、解析器版本 | 解析进度、失败重试与重启恢复 |
| Deck / Module / Chapter | id、父级、排序、规范名称、原始名称、检查状态 | 题库、Java/AI 模块及章节组织 |
| DraftCard | id、chapterId、来源条目、题目、内容块、追问、标记、版本、排除状态 | 尚未确认的候选内容 |
| DraftEditOperation | 操作类型、输入输出 ID、原因、时间 | 追溯合并、拆分、排除引起的数量变化 |
| ChapterCheckProgress | chapterId、当前草稿 ID、检查状态、版本 | 保存检查位置和编辑进度 |
| Card | id、chapterId、draftId、父卡片关联、问题、原文内容、展示修订、版本信息、待检查标记 | 正式学习单位，来源内容与人工纠错分开 |
| SourceSpan / Asset | cardId 或 draftId、PDF 物理页码、页内范围、资源引用 | 支持跨页、多来源范围及图片展示 |
| FollowUp / Tag | 所属卡片、内容、顺序；卡片标签关系 | 追问与多标签；追问不单独调度 |
| PersonalAnnotation | cardId、笔记、提示、记忆要点、收藏、版本 | 个人整理与乐观锁更新 |
| LearningPreference | 每日新题量、复习批量、选中章节、参考时长、版本 | 同步学习偏好 |
| ReviewState | cardId、首次学习时间、lastReviewedAt、dueDate、stage、最近评分、遗忘次数、版本 | 当前调度状态 |
| ReviewEvent | operationId、cardId、评分、前后状态、算法版本、学习日、会话、是否重练、撤销关系 | 可追溯的有效评分历史 |
| LearningSession / SessionItem | 用户、日期、队列条目、当前卡片、状态、重练次数 | 中断恢复、会话进度及有限重练 |
| MutationReceipt / SyncConflict | 操作 ID、请求摘要、结果；冲突两侧内容及解决状态 | 幂等收据和可核对冲突 |
| BackupJob / RestoreJob | 状态、清单版本、校验结果、临时资源引用、错误信息 | 长操作进度与失败恢复 |

内容块建议支持段落、列表、代码、表格、图片、来源片段等类型。保留原始提取结果与人工编辑后的展示版本；技术纠错单独标明，不能覆盖来源证据。一个卡片可以对应多个 PDF 页段，合并、拆分后也不能只剩一个无法解释的起止页码。

### 3.2 状态与约束

- 导入任务状态：`QUEUED → PARSING → READY`，失败进入 `FAILED`，可基于已保存阶段重试；未完成的解析任务不能被当作成功。
- 章节检查状态：`PENDING → IN_PROGRESS → IMPORTED`。异常数量单独统计，已导入不代表全部异常已经消除。
- 章节确认在一个事务中生成正式卡片、来源关联及状态。`draftId → cardId` 映射唯一，重复确认返回原结果。
- 直接上传的文件指纹在用户空间内唯一；同文件重复上传返回已有上传来源和导入进度。P1-09 授权领取的 PDF 使用独立来源和文件副本，允许与已有上传具有相同指纹，不参与上传去重。解析失败时允许重试原任务。
- 正式卡片 ID 稳定。修正内容、章节名称、笔记或收藏都不能替换学习记录；重新学习是单独的显式操作。
- 每个用户每张正式卡片最多一条当前复习状态；历史事件与当前状态在同一事务内更新。
- 文件、草稿、卡片和学习接口都校验用户归属，不能仅凭可猜测的 ID 访问资料。
- 删除题库或重置进度需确认范围，更新同步修订号，并使相关旧会话失效；服务端保留足够的删除信息使其他设备清理缓存。

### 3.3 学习日与统计口径

- 时间戳以 UTC 保存；首版用户学习时区建议固定为 `Asia/Shanghai`，由服务端配置。所有设备使用同一用户时区，不依据浏览器日期统计。
- 服务端生成 `learningDate`，以该时区的自然日为准；首版不开放随意修改时区，避免历史统计归属变化。
- `dueDate` 为用户时区下的日期。到期集合为 `dueDate <= today` 且章节处于学习范围的已学卡片；暂停章节的记录仍保留。
- 未学：没有有效首次评分记录。仅浏览、展开答案或使用提示不会变成已学。
- 今日新学：首次有效评分归属于今日的不同卡片数。同日重练和幂等重试不增加此数量。
- 今日复习：今日有效复习过的不同已学卡片数；同日首次学习后的重练不再算一张复习题。另可记录练习次数，但不能冒充新增已学数。
- 薄弱题首版定义为最近一次有效评分为“不会”或“模糊”的卡片，详情同时展示遗忘次数；收藏与调度无关。
- 总已学与最近评分分开展示，不使用一个“掌握率”代替两个指标。
- 撤销、恢复备份之后按有效事件重新核对统计，不能只对计数器做无依据的累加减。

## 5. 首版复习规则建议

### 5.1 调度规则

为便于实现和验证，P0 采用可配置的阶段算法，版本记为 `rules-v1`。这是设计文档候选间隔的开发细化方案，不声称为适合所有用户的科学最优参数。

- 成功间隔表：`[1, 3, 7, 14, 30]` 天。
- `stage` 初值为 `-1`，表示尚未形成连续成功阶段；首次有效评分后进入已学状态。
- 调度间隔从本次有效评分对应的服务端学习日计算；第 N 天指 `learningDate + N`，不是浏览器时区，也不是必须等满 N × 24 小时。

| 本次评分 | stage 更新 | 下次复习 |
| --- | --- | --- |
| 记住了 | `min(stage + 1, 4)` | 取更新后阶段的间隔；达到 30 天后保持 30 天 |
| 模糊 | `max(stage - 1, -1)` | 1 天后，不延长间隔 |
| 不会 | 重置为 `-1`，遗忘次数加 1 | 1 天后；本轮后部额外安排一次可跳过的重练 |

正常练习若发生在上次有效评分的同一学习日，统一按同日重练处理，避免从题库反复提交把间隔快速推到 30 天。到期判断和参数运算封装为纯函数，传入时间而不直接读取系统时钟。

### 5.2 同日重练与结束条件

- 同一卡片每学习日最多自动追加一次“不会”重练，且每会话最多追加一次，避免退出重建会话后无限追加。
- 重练保留练习事件，但不推进 `stage`、不增加新增已学数，也不另算一张今日复习题。
- 重练再次“不会”可以保留 1 天后的 dueDate；重练“记住了”也不直接跳到下一个间隔。首版重练均不晚于原定 dueDate，最新评分用于薄弱状态展示。
- 允许用户跳过重练并结束会话；卡片继续保留薄弱状态及到期安排。
- 次日及之后的新一次练习按正常调度计算；提前练习会更新安排，界面需明确告知。

### 5.3 撤销与重新学习

- 仅撤销当前用户最近一次、且卡片状态没有后续变更的有效评分；使用版本检查，不能撤销后续评分之下的旧事件。
- 撤销以补偿记录保留审计关系，恢复评分前状态、会话位置及重练安排；第一次评分被撤销后卡片回到未学。
- 若其他设备已经产生后续状态，返回冲突并展示当前结果，不直接覆盖；最近一次撤销窗口建议以当前会话为界。
- “重新学习”需明确确认，使卡片重新进入巩固、dueDate 设为今日，保留历史和首次学习信息，不再次计为新题。

## 6. 同步与并发规则

### 6.1 服务端为准、客户端保存待提交内容

第一版是在线应用。IndexedDB 负责防止刷新和短时断网导致待提交内容丢失，不承担完整题库离线同步和调度。重新联网先检查 `dataEpoch`、登录及实体版本，再重试；遇到过期代次或冲突立即停止相关自动重试。

前端不得把所有错误当成可重试错误：网络异常可按退避重试，字段校验要求用户修正，版本冲突进入解决界面，登录过期先重新认证。

### 6.2 冲突处理表

| 情况 | 服务端行为 | 客户端行为 |
| --- | --- | --- |
| 同操作 ID、同请求内容 | 返回原收据，不再执行 | 使用原结果清理待提交项 |
| 同操作 ID、不同请求内容 | 拒绝请求 | 提示操作异常，保留本地内容供核对 |
| 两设备编辑同一笔记/草稿/偏好 | 一个版本成功，另一个返回当前版本及冲突 | 保留本地和远端值，选择或手动合并后以新版本、新操作 ID 提交 |
| 两设备从同一复习状态提交相同评分 | 首个写入成功，第二个识别为重复候选，不再推进 | 展示已完成结果；不伪造第二条有效评分 |
| 两设备从同一复习状态提交不同评分 | 首个生效，第二个保存为待处理候选，不重复累计 | 展示双方评分和日期，可接受当前值；如选择候选则显式执行一次更正 |
| 学习会话已经被其他设备推进 | 返回最新会话/卡片状态 | 刷新队列；额外练习需用户明确进入 |
| 删除或恢复后仍提交旧修改 | 拒绝旧版本或旧代次 | 保留待提交内容供复制核对，重新获取当前数据 |

评分冲突的显式更正必须基于同一原始评分前状态重算，替换当前冲突链的有效结果，不当成第二次练习；已发生后续学习时不再允许直接替换，应保留候选并提示重新练习。统计仅使用有效结果。

## 7. 备份与恢复实现要求

### 7.1 备份结构

```text
backup.zip
├─ manifest.json       # formatVersion、创建时间、数据数量、算法版本、文件清单及 SHA-256
├─ data.json           # 用户学习空间的结构化数据，不含认证凭据
├─ sources/            # 原 PDF
└─ assets/             # 图片等内容资源
```

- 结构化数据以数据库一致性快照导出；PDF 和资源采用不可变文件引用，导出任务固定清单，在导出结束前不清理被引用文件。
- 清单包含计数、长度及校验和；避免先导出卡片、再导出已变更历史而生成不一致备份。
- 运行中的解析任务恢复为可重试状态，不把旧任务的执行线程状态当作可恢复数据；已保存草稿、编辑和检查进度必须保留。
- 操作收据等传输状态不要求照搬旧代次；需用新的 `dataEpoch` 隔离旧请求，同时保留可核对的学习与冲突记录。

### 7.2 恢复步骤

1. 上传到临时区，限制压缩后/解压后大小、条目数量；校验路径，禁止路径穿越和异常压缩包。
2. 校验格式版本、所有文件校验和、实体关系、来源范围、复习状态和事件一致性。未知新版本明确拒绝，已支持旧版本通过显式迁移处理。
3. 展示备份时间、卡片/章节/草稿/历史数量和替换范围；提供先导出当前数据的入口。
4. 用户确认后，短时阻止该用户业务写入，等待已开始写入事务完成；再次核对确认时的修订号，期间变化则要求刷新影响预览。
5. 将资源放入新的持久化命名空间；数据库在事务内替换当前学习空间，并递增 `dataEpoch` 和 revision。文件准备失败不能先清空数据库。
6. 事务成功后才切换为新数据；资源旧版本延后清理，失败时继续使用旧数据。恢复执行自身以独立任务/请求标识去重。
7. 其他设备发现代次变化，丢弃旧服务端缓存并重新加载；旧待提交内容转为待核对，不自动重放。恢复前会话不可继续写入。

恢复保留复习日期和历史学习日。无需恢复设备滚动位置，不能因当前日期已变化就重新计算备份中的 dueDate。

### 9.1 P1-08：邀请码注册与独立账号

**状态：已完成仓库实现与本地验收（2026-11-01），尚未发布公网。** 已交付 V11 迁移、邀请码注册、密码修改/维护重置、旧预置身份绑定、会话撤销、限流、账号切换与队列隔离、个人及全站配额。前端 117 项、后端 24 项单元测试及 74 项 PostgreSQL 集成测试通过；浏览器及维护命令演练见 [P1-08 验收记录](fixtures/p1-08/README.md)，决策见 [ADR 0014](decisions/0014-p1-08-independent-accounts.md)。注册默认关闭，部署开启与实体设备复验见 [账号维护手册](runbooks/accounts.md)。以下保留本任务的范围及验收要求。注册本身不自动建立好友关系或共享资料。

**建议体验**

- 登录页增加“注册账号”入口，填写邀请码、用户名、密码和确认密码；昵称可选，登录名与显示昵称分开。
- 朋友各有账号和个人学习空间，题库、笔记、收藏、自评、每日计划及备份彼此独立；同一个人在手机和电脑登录同一账号继续同步。
- 注册成功后进入登录页，登录后进入现有首次导入引导。第一阶段朋友自行上传资料；不用等待题库分享功能即可开始使用。
- 小范围试用先采用邀请码，暂不接入邮箱、短信或第三方登录。是否开放无邀请码注册，结合人数、容量和维护需求另行决定。
- 提供登录后的修改密码入口；忘记密码先由部署维护者通过受控命令重置，不提供仅凭用户名重置密码的公开接口。修改或重置密码后撤销该账号已有会话，重新登录。

**开发内容与兼容要求**

1. 复用 `app_user`、BCrypt、Spring Security 会话、CSRF 和同源 Cookie。用户名规范化、长度、保留名、密码规则在接口契约中固化，并以数据库唯一约束兜底；现有登录名必须保持可登录，不能因新规则被静默改名。注册密码不进入日志、浏览器持久化或离线重试队列。
2. 增加邀请码记录，至少保存令牌摘要、有效期、使用上限、已用次数和撤销状态；服务端生成不可预测令牌，明文仅在生成时展示。首版通过部署维护命令生成和撤销，无需先搭建完整后台管理页面。
3. 在同一事务内验证并占用邀请码额度、创建账号及初始化独立 `dataEpoch`、revision 和默认学习设置；并发注册不能超发，用户名冲突或事务失败不消耗额度。注册响应丢失后引导尝试登录，不自动重放注册或再次消耗名额。
4. 注册设可关闭开关，并对注册和登录按可信来源地址、账号等维度限流，返回可理解的错误。无效、过期、撤销和已耗尽的邀请码使用统一提示，不暴露邀请人资料；登录继续使用统一账号或密码错误提示。
5. 调整现有 `AccountProvisioner` 的启动覆盖密码逻辑：旧预置账号保留原用户 ID 和全部数据；迁移后环境变量不能在每次重启时覆盖用户新密码，也不能接管同名注册账号。预置身份绑定与后续重置流程通过新 ADR 明确，发布手册同步更新。
6. 逐项复核题库、导入任务、PDF/图片、复习、同步收据/冲突、备份下载和恢复确认的用户归属。跨用户访问仍按现有契约拒绝；恢复始终只替换当前用户学习空间，不能改变账号凭据、邀请码或其他用户的数据。
7. 切换账号时停止原账号同步、清空页面中的原账号状态并隔离缓存和 IndexedDB 队列；同源其他标签页检测身份变化后也须停止旧请求与重试并重新确认身份，不能仅校验本标签页的旧 `userId`。异步响应不能写入新账号页面；未同步内容保留在原用户范围，仅原用户重新登录后可继续核对或提交。
8. 补齐每用户存储量、来源数量和导入/备份任务并发上限，以及全站容量保护；限额从服务端执行，页面说明剩余额度与超限原因，具体数值在开发时根据现有服务器资源确定。

**已实现接口与模型**

- `POST /api/auth/register`：邀请码、用户名和密码；无需登录但验证 CSRF，成功不自动创建登录态。现有登录、退出和身份接口继续复用。
- `POST /api/auth/password`：验证当前密码后修改密码，完成后要求所有设备重新登录；维护者重置走服务端命令并记录操作结果，不记录密码。
- `RegistrationInvite`：摘要、有效期、额度、撤销及创建/使用记录；账号增加可区分预置/注册来源及凭据变更所需字段。账号和邀请管理数据不进入个人学习 ZIP 备份。
- 已新增 ADR 0014、V11 迁移及 [注册/密码 API 契约](api/registration-and-accounts.md)，固化重启兼容、限流、配额、错误码和会话撤销方式，以链接的契约为准。

**验收条件**

- 有效邀请码可注册并在手机、电脑登录；无效、过期、撤销、耗尽和重复用户名的失败均不留下半成品账号。最后一个名额的并发请求只能成功一次。
- 旧预置账号升级后用户 ID、题库、笔记和学习历史保持不变；修改密码后重启也不会被环境配置覆盖，同名注册不能占用预置身份。
- 用 A、B 两个真实账号验证所有数据入口及猜测 ID 的越权请求；A 的导出、删除、重置和恢复不影响 B。限制不能只依靠页面隐藏。
- A 留有未同步笔记/评分时切换 B，包括另一标签页切换身份的情况，A 的内容和旧响应均不出现在 B 页面或提交到 B；切回 A 后可核对原待提交项。
- 修改/重置密码后旧会话均不能继续读写；注册/登录限流、邀请码关闭、配额拒绝和服务重启有明确可复现的验证记录。

**状态：已完成仓库实现与本地验收（2026-11-01），尚未发布公网。** 已交付 V17、全站概览/每日趋势、逐用户搜索分页与最近活跃/时长排序、单用户每日汇总、前台活动心跳及跨标签页/设备区间并集。上海自然日、有效评分重算、采集起点/未采集与零值、30 天原始区间和 12 个月每日汇总清理均已固化；活动不改变学习修订或个人恢复范围。接口、决策及验证见 [Dashboard API](api/admin-dashboard.md)、[ADR 0020](decisions/0020-p1-14-usage-dashboard.md) 和 [验收记录](fixtures/p1-14/README.md)。以下保留需求与验收标准。

**页面与指标**

- 概览卡片：用户总数、启用/停用数、今日新增用户、当前在线用户、今日/近 7 日/近 30 日活跃用户、有效在线时长、新学/复习题量、存储使用与失败导入任务数。
- 趋势：按日展示活跃人数、有效在线时长与学习量，可选日期范围；逐用户列表支持搜索、分页及按最近活跃/使用时长排序，展示最近登录、最近活跃、在线状态、当期使用天数、新学/复习数量、知识库领取数和存储量。可查看单用户每日汇总，不展示私人学习内容。
- 页面标明统计时区、日期区间、数据更新时间和时长采集起始日；空数据、尚未采集与真实零值分开显示。首期无需实时大屏、排行榜或行为回放。

**统计口径与采集建议**

1. Dashboard 自然日统一采用 `Asia/Shanghai`，时间戳存 UTC，日期区间按该时区边界转换。个人学习日规则不变；如用户学习时区不同，后台按事件时间重新归入看板日期，不直接相加不同学习日的“今日”数字。
2. 活跃用户定义为所选区间内至少发生一次有效前台活动的不同用户，学习活跃另按有效评分去重；新学、复习、撤销与重练沿用第 3.3 节有效事件规则。近期登录、应用活跃和完成学习分别展示，不把心跳当作完成学习。
3. 建议前台可见且最近 5 分钟有键盘、点击、滚动等交互时，每 30 秒上报心跳，仅上传活动时间信息；当前在线定义为最近 90 秒内收到合格心跳。后台标签页、锁屏/休眠、退出、停用和失去会话后停止采集，长时间阅读无交互不计入有效时长，页面明确此口径。
4. 有效在线时长按服务端接收的连续合格心跳区间估算，首个心跳只建立起点，相邻间隔超过 60 秒不补算空档。按用户对所有标签页/设备的时间区间取并集、再按看板自然日切分；断网后不补传长时段，不信任客户端任意累计秒数。浏览器崩溃或丢失退出事件不持续累计，在线宽限窗口也不直接作为有效时长。
5. 心跳由会话确定用户身份，限制频率并去重，携带采集会话标识以关联区间；权限/登录失效后拒绝采集。它独立于学习同步队列和业务修订号，重试不重复计时、不触发所有设备的学习数据刷新。
6. 仅采集必要的活动元数据，不记录按键内容、笔记正文或阅读内容，向用户说明使用统计和管理员可见范围。建议原始心跳/活动区间保留 30 天、每日汇总保留 12 个月，并配置清理任务；实施时在 API、迁移和运维手册中固化保留策略。
7. 管理查询使用服务端聚合与分页，普通用户不能读取其他人的使用情况；后台统计独立于小组自愿摘要权限，不改变 P1-10 的组内分享规则。个人恢复不回滚登录/在线活动、权限或管理审计，学习量按恢复后的有效事件重新核对。

**验收条件**

- 使用管理员和至少两个普通账号核对全站、逐用户、按日汇总；同日多次重练、评分撤销及恢复备份后的学习统计与本人有效记录一致。
- 多标签页及双设备同时在线不重复累计；后台挂页、超过空闲阈值、跨天、断网、崩溃、退出和账号停用均有可复现时长记录，时长不能超过对应区间的自然经过时间。
- 上线前时长显示为“未采集”，不能伪造历史在线记录；看板展示采集起点、更新时间和时区，零使用账号仍出现在用户列表。
- 普通用户调用全站/他人汇总接口被拒绝；无私人内容或凭据泄露；聚合查询与心跳不影响现有学习同步和评分事务。
