## 1. 产品定位与目标

### 1.1 背景

用户正在准备 Java 后端工程师面试，已经拥有 PDF 格式的面试题库，希望像使用背单词软件一样，持续学习和复习后端基础知识。

直接阅读 PDF 能够接触知识，但不容易判断自己能否独立回答，也难以跟踪哪些题目已经学过、哪些知识正在遗忘。因此，需要把现有题库转化为可以主动回忆、评价掌握程度、安排后续复习的学习工具。

### 1.2 产品定位

一个以个人使用为起点、面向 Java 后端面试的知识卡片学习网站，支持在手机和电脑之间同步题库与学习进度。

核心流程：

**导入 PDF → 逐章检查并加入题库 → 自定义学习计划 → 看题并回忆 → 阅读完整答案核对 → 三档自评 → 根据遗忘情况安排复习。**

### 1.3 希望帮助用户做到什么

1. 把已有 PDF 题库整理为可以逐题学习的内容。
2. 在不看答案的情况下，尝试用自己的话解释知识点。
3. 识别“看着熟悉”和“能够独立回答”之间的差别。
4. 优先复习容易忘记的内容，减少反复查找题目的成本。
5. 逐步形成能够在面试中自然表达的答案结构。

学习进度表示用户的学习与自评情况，不代表系统已经验证答案正确，也不代表已经具备对应的面试能力。

## 2. 用户与使用场景

### 2.1 主要用户

准备 Java 后端面试、拥有现成资料，希望利用每天的零散时间系统复习的个人用户。

### 2.2 典型场景

| 场景 | 用户期望 |
| --- | --- |
| 第一次使用 | 导入 PDF，先检查一个章节，确认后即可开始学习 |
| 分批整理题库 | 本次检查 Java 基础，下次继续检查 JVM，保留各章节的检查进度 |
| 每天开始学习 | 直接知道今天有哪些到期题，以及还可以学习多少新题 |
| 学习一道新题 | 先尝试回答，再阅读完整答案，记录自己的理解 |
| 复习已学题 | 检查能否独立说出核心要点，并据此安排下次复习 |
| 某个知识点反复忘记 | 从薄弱题目中找到它，查看自己的笔记并重点练习 |
| 面试前集中准备 | 按 Java、并发、数据库等章节快速筛选题目 |
| 怀疑导入答案有误 | 回到 PDF 对应页核对，修正卡片内容 |
| 更换学习设备 | 在电脑上完成学习后，打开手机能够看到同步后的进度并继续 |
| 备份与恢复 | 导出题库、笔记和学习记录，需要时恢复并继续原有复习计划 |

## 3. 现有题库与内容组织

已检查的文件结构：

- 共 222 页，前 6 页为题目目录。
- 目录包含 158 道主问题，均有能够定位到正文的内部链接。
- Java 后端基础相关内容共 116 道，Agent、RAG、LLM 相关内容共 42 道。
- 部分题目包含“追加”追问，一道主问题的正文可能跨越多页。

以上数量是目录主问题数量，不包含未来手动拆分产生的子卡片，也不代表 158 道题的答案已经逐题校对。

已确认导入的章节可以加入学习范围；已导入但未选中的内容保留在题库中，不进入当前每日学习计划。尚未确认的章节保留为导入草稿，不参与学习。

### 3.3 内容之间的关系

- **题库**：来自一份或多份资料的正式卡片集合，可以逐章补充内容。
- **导入草稿**：已经识别但尚未按章节确认的候选内容，与正式题库分开展示。
- **章节**：按照 Java、JVM、MySQL 等主题组织内容。
- **主卡片**：一道主问题及其答案，是第一版安排复习的基本单位。
- **追问**：挂在主卡片下的深入问题，第一版与主卡片一同查看。
- **学习记录**：用户对某张卡片的学习、自评和下次复习安排。

一张卡片可以同时带有多个标签，但应拥有明确的主要章节，避免分类交叉造成重复学习。

## 4. PDF 导入体验

### 4.1 导入流程

1. 用户选择 PDF，查看文件名称和页数。
2. 系统识别章节、主问题、答案范围和相关追问，形成导入草稿。
3. 展示章节列表、每章候选题数、异常数量和检查状态。
4. 用户选择一个章节，预览该章卡片，对需要处理的内容进行编辑、合并、拆分或排除。
5. 用户确认当前章节，该章卡片进入正式题库；其他章节继续保留为草稿。
6. 用户可以立即学习已导入章节，也可以继续检查下一个章节。
7. 用户自行设置参与学习的章节、每日新题量等学习偏好。

来源资料支持修改显示名称，用于整理资料列表；名称编辑不改变原 PDF 内容或卡片、来源关联和学习记录，并遵循相同的同步确认与冲突处理规则。

检查以章节为单位推进，不要求一次性完成全部 158 道题。章节内支持批量确认，确认前清楚展示仍有多少条内容被标记为待检查；用户可以返回修正，也可以明确选择保留标记后导入。带标记导入的卡片在正式题库和学习页中继续显示提醒。

例如，先检查并导入“Java 基础”17 道主问题，即可开始学习；之后继续处理“JVM”6 道主问题，不影响已完成的学习记录。

### 4.2 逐章检查与进度保存

| 章节状态 | 含义与操作 |
| --- | --- |
| 待检查 | 已识别出候选内容，用户尚未开始检查 |
| 检查中 | 已开始预览或编辑，允许退出后继续 |
| 已导入 | 用户已确认该章，卡片可以进入学习计划；仍有待检查标记时显示剩余数量 |

- 保存当前章节的编辑内容、待检查标记和检查位置，下次继续时无需重新开始。
- 当前章节暂不处理时，可以保留草稿并切换到其他章节。
- 已导入章节再次打开时以查看或修正为主，不能因重复确认而生成重复卡片。
- 暂时退出保留已保存的编辑与检查位置；放弃当前章剩余草稿需明确确认范围和原因，不影响其他章节或已导入卡片。首版结构性的合并、拆分和排除用于确认前，已导入章节的修正保留现有卡片 ID 和学习记录。
- 题库中明确展示已导入章节和待检查章节的数量，避免用户误以为整份 PDF 已完成导入。

### 4.3 当前 PDF 的拆分原则

- 优先依据目录链接和正文标题确定题目边界。
- 同一道题的跨页答案需要合并，不能按“一页一题”生成卡片。
- 去除页码、空白页等与答案无关的内容。
- 保留有意义的段落、列表、代码、表格和图片；无法可靠转换时，标记并提供原文入口。
- 将“追加”内容识别为主问题下的追问，避免误当成下一道主问题。
- 第一版默认一道目录主问题对应一张主卡片，后续可以人工调整。

例如，“说一下 HashMap 底层原理和扩容机制”的内容覆盖第 10–12 页，应先作为一张完整主卡片导入，再由用户决定是否进一步拆分。

### 4.4 导入预览应展示什么

| 内容 | 目的 |
| --- | --- |
| 章节列表、每章卡片数量与检查状态 | 逐章推进，并判断是否存在明显漏题或重复 |
| 题目、答案和追问 | 检查内容边界是否正确 |
| PDF 起止页码 | 方便对照原文 |
| 待检查标记及原因 | 找到数字缺失、乱码、图片或边界不确定的内容 |
| 编辑、合并、拆分、排除操作 | 允许用户修正候选结果 |

目录数量与候选主卡片数量不一致时，应显示差异。用户主动合并、拆分或排除造成的变化，应能够与识别遗漏区分。

### 4.5 异常与重复导入

- 文件无法读取或无法提取足够内容时，说明原因，并保留用户重新选择文件的入口。
- 不确定的文字和数字应标记为待检查，不能依靠猜测静默补全。
- 识别或章节检查中断时保留可恢复的草稿；当前章节未确认的内容不进入正式题库，之前已确认的章节继续可用。
- 取消导入时区分“暂时退出”和“放弃剩余草稿”，放弃草稿不删除已经导入的章节。
- 再次导入相同文件时提示用户，避免意外生成整套重复卡片。
- 题目相似时可以提示可能重复，但不自动合并答案。
- 修改已导入题库时，应保护已有学习记录；内容发生较大变化时，允许用户主动重新学习。

第一版先围绕当前 PDF 的结构做好导入体验。扫描版、复杂多栏排版等其他资料类型暂不承诺同等识别效果。

## 5. 卡片内容设计

### 5.1 一张卡片包含的信息

| 信息 | 展示方式与用途 |
| --- | --- |
| 问题标题 | 卡片正面首先展示，是主动回忆的起点 |
| 章节与标签 | 帮助理解题目范围和筛选内容 |
| 完整原文答案 | 展开答案后直接作为主体展示，保留题库的完整解释和上下文 |
| 回忆提示 / 记忆要点 | 可选内容，帮助建立回答结构 |
| 追加追问 | 主答案之后按需展开 |
| 个人笔记 | 记录自己的表达、例子和容易遗漏的地方 |
| 来源 | PDF 名称及对应页码，可回到原文查看 |
| 适用版本 | 按需填写 JDK、框架或中间件版本；未知时不自动推断 |
| 待检查状态 | 提醒用户哪些导入内容尚未完成核对 |

### 5.2 以完整答案为主的展示方式

已确认以阅读完整答案为主，采用以下阅读顺序：

1. **问题**：只展示题目，让用户独立回忆。
2. **完整原文答案**：点击“展开答案”后直接阅读完整内容，核对自己是否说到了关键点。
3. **可选辅助**：需要时查看回忆提示或记忆要点；不要求先经过摘要才能阅读完整答案。
4. **个人整理**：查看自己补充的要点或表达方式。
5. **追问**：继续练习更深入的问题。

回忆阶段也可以主动查看提示。提示默认隐藏，避免用户一看到关键词就误以为自己已经记住。使用提示后，仍允许用户自评，但提醒其评价的是本次独立回忆的程度。

完整答案需要保留段落、列表、代码、图片和跨页内容的阅读顺序，不能用自动摘要替代。追问可以单独展开，避免干扰主答案的连续阅读。

记忆要点在第一版可以由用户填写，不要求每张卡片都有。未来如引入 AI 提炼，应与原文答案明确区分，并允许核对和修改。

### 5.3 原文、纠错与拆分

- 原文答案保留来源关系，个人整理和纠错内容单独标识，方便核对修改前后的差异。
- 导入预览阶段可以修正排版、内容边界等问题，原始 PDF 保持可查看。
- 对答案本身的技术性修正，不应让用户误以为修正内容来自原 PDF。
- 同一题过长时，可以拆成更小的子问题，并保留与原题的关联。
- 若未来将追问转为独立卡片，应提示其会单独参与复习，避免用户无意中增加大量学习任务。

## 6. 学习与复习流程

### 6.1 每日入口

首页优先回答三个问题：

1. 今天有多少到期题需要复习？
2. 今天计划学习多少新题？
3. 上一次未完成的学习可以从哪里继续？

建议提供“开始今日学习”，同时提供独立的“复习到期题”和“学习新题”入口。默认先处理到期复习，再学习新题；用户可以主动切换。

### 6.2 单张卡片的学习过程

1. 显示问题，答案和提示默认收起。
2. 用户思考、默念或口述自己的答案，不强制输入文字。
3. 用户展开完整答案进行核对，必要时查看可选提示或要点。
4. 阅读自己的笔记或追加追问。
5. 在“不会、模糊、记住了”中选择本次掌握程度。
6. 显示下次复习安排，进入下一张卡片。

评分只在展开答案后出现。系统根据用户自评安排复习，第一版不自动判断口述或输入答案的正确性。

### 6.3 三种自评的含义

| 自评 | 判断标准 | 复习方向 |
| --- | --- | --- |
| 不会 | 想不起核心内容，或回答存在明显错误 | 尽快再次练习，并缩短后续间隔 |
| 模糊 | 能说出一部分，但遗漏关键点或需要较多提示 | 保持较短间隔，继续巩固 |
| 记住了 | 能独立说清核心结构，并解释主要原因 | 逐步延长复习间隔 |

“记住了”表示本次回忆顺利，后续仍然会安排复习。用户可以将已学题重新标记为需要重点学习。

### 6.4 基于遗忘曲线思路安排复习

已确认由系统结合遗忘曲线的间隔复习思路、历史复习情况和三档自评，安排下次复习日期。用户不需要逐题手动填写日期。

- 新题第一次自评后进入复习计划，初期安排更密集的复习。
- 多次选择“记住了”时逐步延长间隔，避免始终按相同周期重复。
- 选择“模糊”时保持较短间隔，或相对原计划提前复习。
- 选择“不会”时缩短间隔，进入重新巩固阶段。
- 到期题中优先关注逾期较久、近期回答较差的内容。
- 当天没有新题目标或新题已经学完时，仍可以正常复习。
- 漏学一天后，已完成的进度保留；未完成的题保留到期或逾期状态，继续出现在待复习列表中，不因跨天自动视为完成或重设到期日期。
- 自评后展示预计下次复习日期，题目详情中可以查看当前复习安排。
- 三档自评是固定的核心操作，不额外增加必须选择的评分等级。

对“不会”的卡片，建议在本轮后部再练习一次。如果仍不会，允许结束本轮并把它留在薄弱题目中，避免单道题让学习流程无法结束。

作为后续讨论的初始方案，连续回忆成功后的间隔可以参考 1 天、3 天、7 天、14 天、30 天，各间隔均从本次有效自评完成后计算。“模糊”或“不会”会使该题偏离这组递增间隔，更早安排复习。

这组天数是候选参数，不作为所有题目和所有用户都适用的固定遗忘曲线。具体参数、同日重练与后续到期安排的关系，留到开发方案阶段确定；“根据自评和记忆情况自动安排日期”的产品要求已确认。

### 6.5 自定义学习习惯

学习习惯由用户自行设置，不预设必须完成的固定学习量。

| 设置项 | 产品要求 |
| --- | --- |
| 每日新题量 | 用户自行设置，允许设为 0，专注复习已有内容 |
| 每次复习批量 | 用户决定一轮处理多少道到期题，便于利用零散时间 |
| 学习范围 | 自行选择已经导入的章节，随时加入或暂停章节 |
| 学习目标 | 可按个人习惯设置每日参考时长，不强制计时或到时结束 |

首次使用时提供建议值供用户修改，后续随时可以调整。具体建议值留到体验设计阶段确定。

- 新题目标只影响尚未开始的新题安排，不重算已完成的学习记录。
- 复习批量只控制本轮数量，剩余到期题继续可见，不改变其到期日期。
- 暂停某章节后，该章不进入每日任务，但题库、笔记和历史记录保留；恢复后重新显示仍需处理的到期题。
- 学习偏好随同一用户在手机和电脑之间同步，切换设备后不必重新设置。

### 6.6 学习量统计与中断恢复

- 到期题较多时，允许分批完成，并明确显示剩余数量。
- 已提交自评的卡片计入完成；仅查看题目或展开答案不算完成。
- 中途退出时保留已完成记录，重新进入可以继续剩余任务。
- 跨设备继续学习时，以已经同步的有效记录为准；同一道题的同一次提交或重复练习不重复计为新增已学题。
- 提交自评后应能够撤销最近一次评分，修正误触。
- 每轮结束后展示新学数量、复习数量和仍需关注的题目；重复练习次数不重复计为新增掌握题数。

“今日任务已完成”表示当前任务已经处理完，不等于所有题目已经掌握。

## 7. 页面与主要操作

### 7.1 首页 / 今日学习

- 展示今日待复习、新题目标、今日完成情况。
- 提供开始学习、继续学习和进入题库的入口。
- 首次没有题库时，引导用户导入 PDF。
- 当前章节没有可学题时，提示调整学习范围或浏览其他章节。

### 7.2 题库页

- 按题库、章节浏览和搜索题目。
- 按未学、已学、到期、薄弱、收藏、待检查等条件筛选。
- 查看题目详情、编辑个人笔记、收藏题目或调整学习范围。
- 搜索或筛选无结果时，提供清除条件的操作。

### 7.3 学习页

- 以当前问题为视觉中心，减少与学习无关的信息。
- 提供展开完整答案、自评和查看来源等主要操作，提示与要点作为可选入口。
- 展示本轮进度，允许退出并稍后继续。
- 从题库主动查看某张卡片时，允许只浏览；明确进入练习并提交自评后，才改变复习安排。

### 7.4 导入与检查页

- 选择 PDF 并查看识别进度。
- 展示章节列表，每章包含候选卡片数量、异常数量和检查状态。
- 在当前章节内编辑、合并、拆分或排除候选结果，再按章节确认加入题库。
- 支持保存草稿、继续上次检查，以及切换到下一个章节。
- 导入后仍能找到待检查卡片并继续修正，不要求处理完所有章节后才能学习。

### 7.5 学习进度与设置

- 查看各章节已学数量、待复习数量和薄弱题目。
- 调整每日新题量、每次复习批量、学习范围和可选的每日参考时长。
- 区分“学过多少题”和“最近自评掌握得如何”，避免用一个百分比混淆两者。
- 第一版不需要复杂排行榜、积分或连续打卡奖励。

### 7.6 用户与同步状态

- 提供识别同一用户和进入个人学习空间的入口，手机和电脑访问同一份个人数据。
- 清楚显示待同步、同步中、已同步、同步失败或有内容待处理等状态。
- 同步失败时提供重试入口，不把尚未保存成功的内容显示为已经同步。
- 尚未确认的上传或编辑在页面刷新后仍可查看；冲突时保留本地与服务端内容，用户可以明确选择重新保存或放弃。恢复数据后的旧修改保留供核对，不自动覆盖恢复结果。
- 具体登录方式和身份验证流程留到后续方案讨论，本版先确定同步体验和数据归属。

### 7.7 备份与恢复页

- 用户可以主动导出完整备份，查看本次包含的数据范围和备份时间。
- 恢复前展示可识别的备份信息、数据范围和对当前数据的影响。
- 恢复涉及替换当前数据时，明确提示，并提供先备份当前数据的操作。
- 恢复结束后展示结果，失败时说明原因，不把未完成的恢复当作成功。

## 8. 体验要求与数据保留

### 8.1 阅读体验

- 支持长答案的自然阅读，避免代码和表格被截断。
- 展开答案后直接显示完整内容，不强制切换到摘要视图；长代码或宽表格可以在内容区域内横向查看。
- 中文正文、英文技术名词和代码应清晰易读。
- 电脑端便于查看长答案和 PDF，手机端便于逐题复习。
- 手机端核心按钮便于点击，电脑端可以后续考虑键盘操作。
- 自评按钮除颜色外还要有清晰文字，不仅依靠颜色区分。

### 8.2 学习记录保留

- 正常关闭并重新打开网站后，题库、个人笔记和学习记录仍应可用。
- 调整章节或每日目标不应清除已有进度。
- 收藏用于标记关注内容，不直接改变复习时间。
- 用户从题库中手动进入薄弱题练习，只有明确提交自评后才更新学习记录。
- 删除题库或重置学习记录前，应说明影响范围并要求用户确认。

### 8.3 手机与电脑之间同步

支持设备间同步是第一版需求，不能只依靠单一设备上的学习记录。用户在手机和电脑上进入同一学习身份后，应能访问一致的个人学习空间。

同步范围包括：

- 已导入题库、卡片内容、章节与标签，以及查看来源 PDF 所需的资料。
- 各章节导入草稿、编辑结果和检查进度。
- 个人笔记、收藏与待检查标记。
- 学习历史、自评结果、下次复习安排和今日完成情况。
- 每日新题量、复习批量和学习范围等偏好。

切换设备时保留已经完成的学习进度，不要求恢复到另一台设备完全相同的滚动位置。尚未提交的回忆不计为完成。

同步体验应满足：

1. 电脑端完成自评并同步后，手机端可以看到相应学习记录和下次复习日期。
2. 在一台设备完成的章节检查，同步后可在另一台设备继续。
3. 两台设备应按同一套学习日口径展示“今日”统计，避免设备日期或时区不同造成重复计数。
4. 网络中断或同步失败时，清楚说明哪些修改尚未同步，并保留待同步内容以便重试；第一版不承诺断网时可完成整套学习流程。
5. 多台设备同时修改同一笔记或提交不同自评时，不应静默丢失内容或重复累加进度。应保留可核对的记录，发生无法自动处理的冲突时提示用户处理。

具体同步时机、冲突合并规则和数据保存方式留到后续开发方案确定。

### 8.4 备份与恢复

第一版提供用户主动发起的完整备份与恢复，用于保留独立副本和找回之前的数据。设备同步负责保持各设备当前状态一致；备份负责保留某个时间点的可恢复数据。

| 备份范围 | 内容 |
| --- | --- |
| 题库与来源 | 正式卡片、章节、标签、追问、来源页码及对应 PDF 资料 |
| 导入进度 | 尚未确认的章节草稿、编辑结果和检查进度 |
| 个人整理 | 个人笔记、收藏、纠错内容和待检查标记 |
| 学习记录 | 学习历史、自评、下次复习日期及完成记录 |
| 学习偏好 | 每日新题量、复习批量、学习范围等设置 |

- 导出后保留当前数据，用户可以继续正常学习。
- 恢复前检查备份是否可用，展示备份时间、题库数量和数据范围。
- 第一版以恢复完整备份为主，不默认把两套学习历史自动合并。
- 需要替换当前数据时，先说明影响范围并由用户确认，同时允许先导出当前数据。
- 恢复成功后保留原有复习日期；已经过期的题继续显示为待复习，不因恢复而重新计时。
- 恢复结果应同步到该用户的其他设备，避免旧设备随后把恢复前的状态静默覆盖回来。
- 无效或不兼容的备份应给出原因，恢复失败时保留原有可用数据。

第一版使用完整 ZIP 备份，用户可以在后台生成完成后下载，也可以上传 ZIP 校验后明确确认替换。当前仅支持格式版本 1、最大 50 MiB 的 ZIP；下载与上传副本在服务端保留 7 天，应将需要长期保存的副本下载到自己的设备。备份不包含账号密码或登录凭证，恢复目标始终为当前登录用户。确认期间当前数据有新修改时，需要刷新影响预览后再次确认。其他设备的旧待提交内容保留供核对，不自动覆盖恢复结果。

自动备份、历史版本保留数量和部分数据恢复方式留到后续讨论；第一版不要求定时自动备份。

## 9. 第一版范围与后续方向

### 9.1 第一版建议包含

| 能力 | 第一版目标 |
| --- | --- |
| 当前 PDF 导入 | 识别主问题、章节、跨页答案和来源页码 |
| 导入检查 | 按章节预览、标记异常、编辑题目边界、保存草稿和逐章确认 |
| 题库管理 | 章节浏览、搜索、筛选、收藏和个人笔记 |
| 主动回忆与完整阅读 | 隐藏答案、展开完整答案核对，提示和要点按需查看 |
| 自评与复习 | 三档自评、根据遗忘情况自动安排日期、到期复习 |
| 每日学习 | 自定义新题量、复习批量与学习范围，中断后继续 |
| 基础进度 | 区分已学、到期和薄弱内容 |
| 原文核对 | 从卡片回到 PDF 对应页面 |
| 用户与设备同步 | 同一用户在手机和电脑间同步题库、导入检查进度、笔记、学习记录和偏好 |
| 记录保留 | 重新打开或切换设备后可以继续学习，清楚展示同步状态 |
| 备份恢复 | 主动导出完整备份，确认影响范围后恢复，并同步恢复结果 |

第一版以个人使用为起点，需要提供同一用户在不同设备访问个人数据的能力。具体账号和登录形式后续确定，不将公开题库分享、社交或多人协作作为首版要求。

### 9.2 后续可以讨论

- 更多 PDF 格式、扫描版识别，以及其他资料导入方式。
- AI 辅助提炼要点、生成追问或检查回答。
- 将长题目拆成多张关联卡片，并单独安排复习。
- 录音、语音转文字、模拟面试和限时口述。
- 按面试日期调整学习安排。
- 自动备份、历史版本管理、部分数据恢复和多个题库的统一管理。

以上扩展不作为第一版默认要求。手机与电脑同步、用户主动备份恢复已纳入第一版范围。

## 10. 第一版是否可用的判断标准

1. 能够导入当前 PDF，并按章节展示与目录主问题相对应的候选卡片；数量差异可以解释和检查。
2. 可以先检查并确认一个章节，立即开始学习；其余章节保持草稿，退出后可以继续检查。
3. 展开后能连续阅读完整答案，包括跨页内容；追问与主问题关联，无法可靠处理的内容有明确标记。
4. 每张正式卡片能够追溯到对应 PDF 页面，手机和电脑均可查看来源。
5. 用户能够独立完成看题、回忆、阅读完整答案和三档自评的流程。
6. 系统根据自评和历史复习情况安排下次复习日期，记忆稳固时逐步延长间隔，遗忘时提前复习。
7. 用户可以自行调整新题量、复习批量和学习范围，不清除已有进度，也不隐藏尚未完成的到期题。
8. 中断、重新打开或调整学习范围后，已经完成的记录不会意外丢失。
9. 用户能够找到反复遗忘的内容，修正笔记后再次练习。
10. 手机和电脑上都能完成核心学习操作，完整答案保持可读。
11. 同一用户在一台设备完成学习、编辑笔记或检查章节并同步后，另一台设备能看到结果；重复提交不重复计数，同步失败有明确提示。
12. 可以导出完整备份并恢复；恢复前明确影响范围，成功后原有复习日期保留，其他设备获取恢复后的数据。

实际使用后重点观察：用户是否更容易开始每天的复习、是否减少了寻找资料的时间，以及隔几天后能否更完整地独立回答。具体指标目标应在有真实使用记录后再确定。

## 11. 已确认结论与后续讨论

### 11.1 本轮已确认结论

| 讨论项 | 已确认结论 |
| --- | --- |
| 学习习惯 | 由用户自行设置，支持调整每日学习量和学习范围 |
| 内容深度 | 主要阅读完整答案，简短提示和提纲作为可选辅助 |
| 复习方式 | “不会、模糊、记住了”三档足够，结合遗忘曲线思路自动安排复习日期 |
| 导入检查 | 按章节逐个检查，逐章确认，已确认章节可以先开始学习 |
| 设备与记录 | 同时支持手机和电脑，并同步同一用户的数据与进度 |
| 备份恢复 | 纳入第一版，先提供用户主动发起的完整备份与恢复 |

### 11.2 后续需要细化的内容

1. **复习安排**：初始间隔参数、遗忘后的调整幅度，以及同日重练如何影响下次复习日期。
2. **首次使用体验**：各设置项的建议值、学习目标展示方式和首个章节的引导。
3. **登录与同步**：同一用户的识别方式、同步时机，以及同时修改时的处理规则。
4. **备份恢复扩展**：自动备份、历史版本保留和部分恢复；完整 ZIP 与明确确认替换已确定。

这些细节不改变本轮已经确认的六项产品要求。后续以本设计文档为依据，再讨论技术选型、数据保存方式、PDF 处理方法、开发顺序和部署方式。
